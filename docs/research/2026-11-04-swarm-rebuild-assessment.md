# Swarm Rebuild의 GX Design 적용 검토

조사일: 2026-11-04. 사용자 설명은 Cursor 앱이 아니라 크롬 등에서 사용하는 확장 프로그램이다. 이에 가장 잘 맞는 후보는 DhvanilPatel/swarm-cursors의 **Swarm Rebuild 1.1.0**이다. 사용자가 본 링크·화면과의 동일성은 아직 확정되지 않았다.

확인 소스: main 커밋 `18fd2614ebea68e64f05a8d269d27de022d50cc9`, 2026-10-15. README·manifest·background·swarm 소스를 정적으로 열람했고 별도 검토자의 판단도 대조했다. 설치·실행·화면 충실도·성능 검증은 하지 않았다.

## 실제 기능

Swarm Rebuild는 기존 페이지를 읽어 여러 커서가 다시 만드는 듯한 장면을 재생하는 Chrome 확장이다. 원본은 Joel Califa의 Swarm 사이트이며, 확장 작성자는 이 사이트의 모션 엔진을 바탕으로 임의 페이지를 읽는 기능을 추가했다고 설명한다. [README](https://github.com/DhvanilPatel/swarm-cursors/blob/18fd2614ebea68e64f05a8d269d27de022d50cc9/README.md).

동작은 다음과 같다.

1. 실제 페이지의 DOM·계산된 스타일을 읽어 박스·텍스트·미디어·반복 요소·정렬선의 시각 청사진을 만든다.
2. 별도 화면 레이어로 원래 페이지를 덮는다.
3. 커서가 박스를 그리고 글자를 입력하며 반복 요소를 복제하는 장면을 스크립트로 재생한다.
4. Tour·속도 조절·Replay를 제공하며 Go live로 원래 클릭 가능한 페이지를 다시 보여준다.

구현의 `captureModel`은 실제 요소의 스타일·좌표를 수집한다. 반복 요소는 태그·클래스·자식 구성·크기 유사성으로 묶는다. 이는 시각 재구성을 위한 추정이며 원래 React 컴포넌트·디자인 토큰의 의미·업무 상태를 복원한 결과가 아니다. [swarm.js](https://github.com/DhvanilPatel/swarm-cursors/blob/18fd2614ebea68e64f05a8d269d27de022d50cc9/swarm-rebuild/swarm.js).

화면에 보이는 여러 커서는 실제 AI 에이전트가 각각 디자인을 판단하는 구조가 아니다. 기존 청사진의 작업을 수행하는 연출이다. README도 재구성 레이어에서 원래 페이지 스크립트가 동작하지 않는다고 명시한다. 따라서 장면 완성은 앱 기능·UX·접근성 검증이 아니다.

## GX에서 얻을 수 있는 가치

| 적용 영역 | 판단 | 구체 활용 |
|---|---|---|
| 완성 페이지 소개·포트폴리오 | 선택적으로 유용 | 화면이 만들어지는 듯한 영상·발표 연출 |
| 현행 화면의 구조 파악 | 추출 방식의 아이디어가 유용 | 박스·정렬·반복 요소를 캡처와 함께 진단 입력으로 정리 |
| 브랜드·스타일 보존 | 보조 가능성 | 실제 계산 스타일을 기존 토큰·컴포넌트와 대조. 의미 토큰을 자동 복원했다고 보지 않음 |
| before/after 설명 | 보조 가능성 | 같은 조건에서 실제 변경을 비교하고 선택적으로 과정 연출 추가 |
| 사용자 의도·응답 대기 | 직접 해결하지 않음 | 기존 GX의 질문·결정 계약을 유지 |
| 독립 검수·과업 성공 | 대체 불가 | 실제 원본·수정본에서 클릭·입력·오류 복구를 별도 확인 |

위 '보조 가능성'은 GX 적용 제안이며 효과를 측정한 결과가 아니다. 특히 청사진을 생성하는 것과 디자인 문제를 판정하는 것은 별개의 작업이다.

## 권장 도입 방식

핵심 워크플로우에는 확장 전체를 기본 의존으로 넣지 않는다. 기존 브라우저 증거 수집에 필요한 영역의 좌표·계산 스타일·반복 구조 요약을 추가하는 작은 실험부터 검토한다. 기존 정본이 있으면 그 토큰·컴포넌트가 우선이며 수집 결과를 새 디자인 시스템으로 자동 확정하지 않는다.

실험 흐름은 `원본 캡처·상태 기록 → 관련 요소의 구조 요약 → 과업·브랜드와 대조한 진단 → 승인된 범위 수정 → 같은 데이터·폭·상태로 비교`다. 새 확장이나 별도 에이전트가 필수인 것은 아니며, 이미 사용 가능한 브라우저 관측 수단을 우선한다.

제품 소개 결과물에 한해서는 선택 연출로 검토할 수 있다. Stageshow가 메시지에 맞춰 새 제품 장면을 작성하는 쪽이라면, Swarm Rebuild는 이미 존재하는 페이지를 재구성하는 장면에 가깝다. 앱 안의 실제 폼·버튼 검증과 소개 장면 검증은 분리한다.

GX 작업 상태를 보여주기 위해 이 커서 연출을 사용하더라도 실제 작업자 수·진행률·승인 상태의 증거로 쓰지 않는다. 제작 과정 재현이라는 사실과 실제 작업 로그를 구별해야 한다.

## 제한과 재사용 조건

README는 일부 의사 요소 제외, 애니메이션 정지, 첫 화면 밖 canvas·video·iframe 자리표시자, 약 4,000개 레이어·40,000px 제한을 기재한다. 원본의 모든 상태·동작·반응형을 재현한다고 가정하지 않는다. 소개 연출의 캡처를 실제 앱 검수 증거로 사용하지 않는다.

저장소는 아직 라이선스가 없으며 원작자에게도 코드 재사용을 확인해 달라고 명시한다. 따라서 현재 GX에 소스를 복사·번들하는 안은 보류하고 개념 참고 또는 별도 도구 평가로 한정하는 편이 적절하다. [라이선스 안내](https://github.com/DhvanilPatel/swarm-cursors/blob/18fd2614ebea68e64f05a8d269d27de022d50cc9/README.md#license).

향후 구조 요약 실험은 캡처만 사용한 진단과 비교해 위치·반복·보존 조건의 정확성, 잘못된 그룹 추정, 수집·검토 비용을 측정한다. 연출이 실제 변경·기능과 혼동되지 않는지도 확인한다. 이 실험은 아직 수행하지 않았다.

## 최종 판단

기존 GX 개선 순서는 유지한다. 사용자 결정·대기, 최종 버전 검수, 범위 내 품질 기준이 우선이다. Swarm Rebuild에서는 **화면 구조를 관측하는 접근**을 작은 실험 후보로, **다중 커서 재구성 장면**을 선택 소개 기능으로 추가한다. 디자인을 자동 개선하는 핵심 엔진으로 취급하지 않는다.
