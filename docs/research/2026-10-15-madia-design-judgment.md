## 실제 조사 범위

**채널의 공개 목록을 끝까지 수집했으며, 전편을 시청·분석한 것은 아니다.** 확보 가능한 공식 설명·챕터와 공개 전사 일부를 근거로 1차 반영했다. 전체 자막·수정 전후 본편 화면 분석은 남아 있다.

| 작업 | 결과 | 의미와 한계 |
|---|---:|---|
| Videos 탭 끝까지 조회 | 884개, 30페이지 | 수집 시점에 공개된 탭의 제목·ID 목록. 채널의 비공개·멤버십·삭제 영상 포함 보장 없음 |
| Shorts 탭 끝까지 조회 | 468개, 10페이지 | 공개 쇼츠 목록. 본편 재편집 중복 가능 |
| Live 탭 확인 | 해당 탭 미제공 | 라이브가 과거에도 없었다는 의미는 아님 |
| 장편 후보 선별 | 307개 | 제목의 컨펌·피드백·위계·폰트·가독성·설계 등 키워드로 탐색. 제목만으로 원칙을 도출하지 않음 |
| 장편 공식 메타데이터 수집 | 225개 성공, 82개 HTTP 429 | 제목·저자·설명·자막 트랙 정보. 후반 속도 제한으로 수집 종료; 실패를 성공으로 세지 않음 |
| 쇼츠 공식 설명 검토 | 선별 30개 | 29개는 구체적 판단, 1개는 주제 소개뿐이라 규칙 근거에서 제외 |

| 공개 전사 미리보기 | 장편 중 2개 | Glasp `Transcript` 일부. AI 요약·Q&A는 직접 발언 근거에서 제외 |
| 자막 전문 확보 | 0개 | 트랙 존재와 전문 확보를 구분 |
| 수정 전후 본편 프레임 검사 | 0개 | 플레이어·썸네일 확인을 본편 분석으로 세지 않음 |

메타데이터 225개의 수집과 판단 근거로 선별한 장편 20개의 검토는 별개다. 인벤토리의 `review_status`가 두 범위를 구분한다. 명부 전체를 분석 완료라고 표시하지 않았다.

수집은 비로그인 공개 채널 탭·공개 watch 페이지로 수행했다. 로컬 계정의 인증 정보·쿠키나 유료 원본 파일은 사용하지 않았다. 자막 URL은 빈 응답, 공개 transcript 요청은 `400 FAILED_PRECONDITION`으로 전문 확보에 실패했다. 설명 수집의 HTTP 429 발생을 기록했으며 추가 대량 수집은 중단했다. 향후 재수집은 기존 인벤토리의 미확인·실패 항목을 기준으로 수행할 수 있다.

## 관찰과 gx 적용의 구분

| 반복해서 확인한 관점 | 직접 근거 | gx에 구성한 판단 |
|---|---|---|
| 화면이 수행할 일을 먼저 확인 | 여행 앱 M01, AI 채팅 M02, 주문서 M03 | 주 과업·필수 정보·관련 상태를 먼저 정의하고 검토 |
| 중요도는 요소 사이의 관계에서 드러남 | M05·M07·M11, S01·S03·S06·S16 | 크기·채도·면적·굵기·주변 여백을 함께 보고 시선 경쟁을 진단 |
| 정보의 묶음이 읽힘을 좌우 | M02~M04, S04·S05·S07·S18 | 내용의 의미 관계와 내부·외부 간격, 정렬·배경·카드를 대조 |
| 글자의 주된 역할은 읽히는 계층 | M04·M07·M12, S02·S17 | 실제 콘텐츠로 제목·본문·보조·행동의 역할과 강약을 점검 |
| 효과는 맥락에서 판단 | M04·M06·M08, S01·S06·S14·S29 | 전달을 방해하는 경쟁·중복만 줄이고 상태·경고·브랜드 의미는 보존 |
| 사이트 성격에 따라 비중이 달라짐 | S08~S13·S24·S28 | 크게 만들기와 상품 밀림, 여백과 분절을 함께 비교 |
| 시스템과 벤치마킹은 사용 조건을 포함 | M08~M10·M13~M15·M17 | 현재 과업과 콘텐츠에 맞는지 확인하고 토큰·컴포넌트의 필요한 변형을 유지 |

이 표의 gx 적용과 순서는 조사자가 만든 운영화다. 제작자의 고정 사고 순서, 모든 프로젝트에 적용되는 법칙, 사용성 실험으로 입증된 결과라고 주장하지 않는다. 관점이 모두 한 채널에서 나온 것이므로 독립 기관의 검증과도 구분한다.

## 반례를 함께 보존한 이유

- **크기**: S12·S28의 과감한 제목·여백 시도와 S10의 첫 화면 상품 밀림, S11의 사이트 성격 조건을 함께 반영했다.
- **여백**: S04·S07의 그룹 유지와 S13의 해상도 채우기용 빈 공간 경계를 함께 반영했다.
- **묶음**: S04의 정보 정리와 S05의 세부 박스화로 생기는 무게를 함께 반영했다.
- **색**: S01·S15의 강약과 S06의 배경이 내용보다 강해지는 역효과를 함께 반영했다.
- **단순함**: M01의 상태·예외 보존과 M03의 정보 관계를 유지하도록 했다. 장식 축소를 정보 삭제로 해석하지 않는다.

예시 픽셀값, 특정 회색, 모든 카드·큰 배너·글래스 금지, 모든 페이지의 미니멀화는 새 규칙으로 채택하지 않았다. 대비와 조작성 수치는 실제 배경·뷰포트·플랫폼·제품 시스템에서 확인한다. 접근성은 [W3C 대비 해설](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [W3C 타깃 크기 해설](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)과 대조했다.

## 반영 위치와 동작

1. `gx-design` 제작: 승인된 목적에서 정보 우선순위·묶음·필요 상태를 정의하고 표현을 선택한다.
2. `gx-redesign` 진단: 실제 관찰한 문제와 영향 가설을 구분하며, 변경 방향과 확인 방법을 기록한다.
3. `gx-redesign` 전략·제작: 진단 문제 또는 승인 목표에 연결된 변경과 유지 조건을 전달한다.
4. `creative-production`·제작 에이전트: 직접 사용해도 같은 판단 절차에 닿는다.
5. `creative-review`·축 B·렌더 품질 루프: 목적과 화면을 대조하고 같은 조건에서 수정 결과·회귀를 확인한다.
6. 리디자인 축 C: 원래 진단 문제의 해소와 유지 조건을 대조한다.

세부 스타일 수치는 기존 VISUAL-CRAFT, 실물 확인은 VISUAL-QUALITY를 정본으로 유지한다. 오케스트레이터에 전체 규칙을 반복 복제하지 않았고, 일상 실행은 공유 판단 문서만 조건부로 읽는다. 새 외부 스킬 설치나 영상 서비스 연결은 필요하지 않다.
PR 준비 과정에서 최신 main의 UI-QUALITY와 검수 ID 계약에 맞춰 통합했다. 진단·상태·실행 로그를 중복 생성하지 않고, 리디자인의 기존 `변경 ID → before → after → 근거` 4열 기록을 유지한다.
동작 평가에서 기존 ANTI-TELL의 카드 개수·내비게이션 문구가 과업 중심 판단과 충돌할 수 있다는 지적이 나왔다. 해당 문구는 정보 역할과 실제 영향으로 판정하고, 필요한 반복·사이드바는 보존하도록 명확히 했다.

## 검증과 남은 범위

검증 결과는 [동작 평가 기록](2026-10-15-madia-validation.md)에 기록한다. 구조 검사만으로 모델의 실제 행동을 보장하지 않으므로 별도 요청 예시 평가도 수행한다.

작업 대상은 이 저장소의 소스다. 설치된 플러그인 캐시 수정·릴리즈·재설치는 수행하지 않았다. 반영본을 사용하는 환경은 이 저장소의 최신 스킬 파일을 로드해야 하며, 설치본은 기존 릴리즈 절차를 거쳐야 한다. 미확인 영상의 전문·화면 분석과 장기 실사용 평가도 남아 있다.
