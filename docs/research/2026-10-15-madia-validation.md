# 판단 절차 검증 기록

일자: 2026-10-15. 대상: [DESIGN-JUDGMENT.md](../../skills/gx-design/DESIGN-JUDGMENT.md) 및 연결 지침.

## 독립 요청 예시 평가

skill-creator의 independent forward-testing 절차로, 조사 결론과 의도한 정답을 전달하지 않은 별도 에이전트가 지침과 원시 자산만 읽고 세 요청을 수행했다. 외부 서비스·실제 제품 수정 없이 진단과 제작 명세를 반환했다. A는 로컬 HTML을 Chrome/Playwright로 렌더한 실제 스크린샷도 직접 확인했다.

| 요청 | 관찰된 응답 | 판정 범위 |
|---|---|---|
| A. 환불 운영 대시보드의 최소 개입 진단 | 실제 스크린샷과 HTML을 대조. 홍보·메뉴·요약의 강조 경쟁과 상세 진입 누락을 위치별로 지적. 관찰과 영향 가설, 유지 조건, 검증 계획을 구분. 카드 개수나 브랜드색 자체를 결함으로 만들지 않음 | 요청된 진단 행동 확인. 수정 결과·사용성 개선은 미검증 |
| B. 전문 바이어의 상품 비교 화면 신규 명세 | 반복 비교에 맞는 고밀도 표와 기존 타입·간격을 사용. 큰 캠페인 영역을 추가하지 않고 수량 입력·정책 의존 상태·모바일 접근·검수 조건을 명시 | 명세 행동 확인. 실제 데이터·렌더·조작 검증은 미수행 |
| C. 큰 사진·여백을 유지하는 가구 캠페인, 명세만 제공 | 승인된 큰 비주얼을 보존. 80vh 자체를 결함으로 단정하지 않고, 크롭·제목 겹침·대비·상태를 추가 확인할 대상으로 분리 | 근거 한계·목적별 예외 처리 확인. 화면 품질은 미확인 |

평가 중 ANTI-TELL의 동일 카드 개수 및 데스크톱 내비게이션 규칙과 과업 중심 판단의 충돌 가능성이 발견됐다. 해당 규칙과 creative-review의 판정 문구를 좁혀, 정보 역할·실제 영향으로 판단하고 필요한 반복·사이드바는 보존하도록 수정했다.
수정 뒤 사례 A를 재평가해 카드·사이드바는 유지하면서 실제 강조 경쟁·상세 진입·대비 문제를 지적하는 결론이 유지됨을 확인했다. 후속 지적에 따라 기록 누락의 일괄 Major 하한도 없애고, 관찰과 예상 영향으로 심각도를 정하며 미측정 영향은 가설로 표시하도록 명확히 했다.

이는 별도 에이전트의 제한된 예시 평가다. 이후 실제 CLI에서도 아래의 제한된 점검을 추가했다. 다회 반복·장기 사용성 검증은 수행하지 않았다.

## 구조·근거 검사

PR은 최신 `origin/main`의 `48adf4e`를 기준으로 별도 작업 브랜치에서 준비했다. 후속 요청에 따라 `git fetch origin`과 `git pull --no-rebase origin main`을 실행해 이미 최신 상태이며 main이 PR 브랜치의 조상임을 확인했다. 최신 모션·호스트 호환·실행 예산·UI 품질 계약을 보존하고, 기존 진단/목표/상태/여정/변경 ID와 4열 변경 기록에 새 판단 절차를 연결했다. 이 과정에서 기존 polish 경로와 유지보수 문서에 남아 있던 3열 안내를 발견해 일반 리디자인과 같은 `변경 ID → before → after → 근거` 4열로 통일했다. 수정 후 `python -X utf8 -m unittest discover -s tests -v`로 저장소의 기존 테스트 76개를 다시 실행해 모두 통과했다.

- 변경한 네 스킬의 기존 YAML frontmatter는 HEAD와 동일함을 확인했다.
- skill-creator `quick_validate.py`는 Windows 기본 cp949에서 UTF-8 문서를 읽지 못해 `python -X utf8`로 실행했다.
- `creative-production`, `creative-review`는 원본 그대로 검증을 통과했다.
- `gx-design`, `gx-redesign`은 기존 Claude용 `argument-hint`를 공통 검증기가 지원하지 않아 직접 실행이 실패했다. HEAD의 변경 전 원본도 같은 오류임을 재현했다. 최신 main의 description에 있는 호출 예시 꺾쇠도 공통 검증기는 허용하지 않는다. 배포 파일의 메타데이터는 보존하고, 임시 복사본에서 `argument-hint`와 description의 예시 꺾쇠만 제외한 공통 형식 검사는 네 스킬 모두 통과했다. 이를 전체 Codex 설치 호환성 통과로 표현하지 않는다.
- 공개 목록 ID의 유일성, 225+30개 확인 성공·82개 실패 상태, 근거 지도의 50개 영상 참조, 판단 근거로 연결한 49개와 불충분 1개, 전사 일부 2개, 전문·본편 프레임 검사 0개 표기의 일관성을 검사했다.
- 변경 문서의 로컬 링크와 근거 ID, 인벤토리 URL의 영상 ID 일치 여부를 검사했다.
- `git diff --check`로 공백 오류를 확인했다.

## 실제 CLI의 제한된 점검

같은 환불 대시보드 HTML과 1365×1000 스크린샷으로 핵심 모드·점검 전용 요청을 실행했다. 주 과업은 내일 마감 환불을 찾아 요청 내용을 확인하는 것이며, 브랜드색·메뉴·주문·기한·금액·정책 보존, 위임·브라우저·웹 검색·파일 수정 금지를 명시했다. 기존 예시 A와 같은 고정 자산을 사용했으므로 새로운 제품 전반으로 일반화하지 않는다.

| 대상 | 직접 확인한 결과 | 한계·판정 |
|---|---|---|
| Codex CLI 0.160.0 격리 설치 | 임시 `CODEX_HOME`에서 로컬 마켓플레이스 등록 → 플러그인 설치 → 목록 확인 성공. 여섯 스킬과 DESIGN-JUDGMENT·출처 지도, 총 8개 파일의 SHA-256이 현재 소스와 일치 | 패키징·참조 동봉 확인. 기존 사용자 설치와 캐시는 변경하지 않음 |
| Claude Code 2.1.300, 로컬 `--plugin-dir` | 도구 로그에서 gx-redesign·DESIGN-JUDGMENT·REVIEW-AXES·creative-review·HOST-COMPAT·REDESIGN-INTERVIEW·UI-QUALITY·ANTI-TELL 및 이미지·HTML의 Read 확인. 과업과 무관한 배너, 마감 신호, 요청 상세 진입, 활성 메뉴를 D-01~04로 진단하고 축 A/B를 별도 절로 보고. Major/Minor는 과업에 미칠 영향으로 판정하고, 영향은 휴리스틱 추정으로 표시. 브랜드색 자체나 카드 개수를 결함으로 만들지 않음. 종료/리디자인/polish 선택을 제시하고 수정하지 않음 | 새 판단 절차·필수 검수 참조·축별 보고·수정 전 선택 확인. 한 화면의 점검 전용 요청으로, 제작·수정·전체 검수 계약 통과까지 판정하지 않음 |
| Codex CLI 0.160.0, 소스 직접 읽기 | 이미지 확인 후 `Get-Content`가 `blocked by policy`로 거부됨. 스킬과 HTML을 읽지 못했다고 응답에 명시 | 스킬 직접 읽기·전체 적용 판정 보류. 플러그인 결함이나 정상 동작으로 단정하지 않음 |
| 같은 Codex CLI, 본문 제공 방식 | 명령 실행 없이 스킬·참조 9개와 HTML을 입력에 제공하고 이미지를 첨부. 축 A/B를 나누고 D-01~04의 관찰·과업 영향·변경 방향·확인 기준을 연결. 유지 조건, 미검증 상태와 종료/리디자인/polish 선택을 명시. 호출 로그에 도구 사용 없음 | 지침을 제공했을 때의 해석·적용만 확인. 자동 스킬 발견·참조 파일 직접 로드·제작 완료까지의 검증을 대신하지 않음 |

초기 Claude 점검은 새 판단 지침을 읽었으나 REVIEW-AXES·creative-review를 건너뛰고 축 A/B를 합쳐 보고했다. 진단 완료 조건에 필수 검수 참조와 축별 보고를 한곳에서 재확인하도록 보강한 뒤, 같은 요청으로 다시 실행해 두 파일의 Read와 A/B 분리를 확인했다. 위 표는 보강 후 결과다. Codex 본문 제공 점검은 이 완료 안내 보강 전에 실행했으며 새 판단 지침 내용은 동일하다.

Claude 도구 로그를 확인한 실행과 Codex 본문 제공 실행은 전후 해시와 파일 목록을 비교해 두 입력 자산이 그대로이며 추가 산출물도 없음을 확인했다. 호스트별 응답의 길이와 참조 이행 차이가 있어 이를 동일 조건의 성능 비교나 전체 파이프라인 합격으로 표현하지 않는다. 실제 신규 제작·리디자인 수정 후의 렌더·상태 회귀, 실서비스 기능, 과업 성공률은 이번 CLI 점검 범위 밖이다.

Codex 명령 차단은 해당 중첩 실행의 환경 제약으로 기록했다. 사용자 전역 설정·실행 규칙을 바꾸거나 차단된 명령의 권한을 확대하지 않았다. 권한 진단의 참고는 [OpenAI Docs의 Windows sandbox 안내](https://learn.chatgpt.com/docs/windows/windows-sandbox)이며, 이 안내만으로 이번 차단의 구체 원인이 확정되지는 않는다.

실제 서비스의 화면·제품 코드는 변경하지 않았다. 저장소의 기존 테스트, 문서·근거 구조 검사와 위 요청 예시·CLI 점검을 사용했으며, 실제 제품의 브라우저 기능·사용성 검증은 수행하지 않았다.

## 0.13.0 버전 점검

기능 추가에 맞춰 Claude Code·Codex 매니페스트의 기본 버전을 0.12.1에서 0.13.0으로 올리고 기존 버전 일치 검사의 목표도 함께 갱신했다. 변경 후 테스트 76개와 `git diff --check`가 통과했다. 새 임시 `CODEX_HOME`에서 0.13.0 설치·목록 확인과 여섯 스킬·판단 지침·출처 지도 총 8개 파일의 소스 일치도 재확인했다. 버전 변경은 앞서 기록한 실행·사용성 검증 한계를 해소한다는 뜻이 아니다.
