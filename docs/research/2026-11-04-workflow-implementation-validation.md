# GX Design 0.14.0 구현 및 검증

일자: 2026-11-04. 기준 커밋: `d7a8c50`. 작업 브랜치: `codex/gx-workflow-quality`.

사용자가 승인한 [최종 개선안](2026-11-04-gx-workflow-final-improvement-proposal.md)과 구현 중 추가한 소요시간·진입 부담 개선 요청을 반영했다. 기존 체크아웃의 조사 문서는 보존하고 별도 작업 공간에서 변경했다.

## 반영한 동작

- 필수 결정별 응답 대기, 빈/부분/취소/늦은 답 처리, 현재 범위의 승인 재사용과 변경 영향 규칙을 통일했다.
- 명확한 점검·부분 수정은 대상 자료·관련 의존 관계만 확인하고 직접 처리한다. 점검 보고 후 종료 선택과 이미 정한 실물 제작 승인을 반복하지 않는다.
- 최종 산출물 버전·데이터·상태·뷰포트·환경에 검수를 연결하고 범위 내 필수 결함·미검증·예외 수용을 구분한다.
- 제작·검수 수정은 단일 총예산을 공유한다. 관찰은 수행하되 결함이 없으면 수정하지 않는다.
- 평가 러너는 현재 결정 ID·유형·범위 버전에 맞는 답만 전달한다. 필수 미응답을 모델의 자체 선언만으로 취소할 수 없으며, 완료 뒤 남은 승인 답변을 전송하지 않는다.
- 파일 해시와 관측 가능한 변경 이벤트, 대화/실물 별도 점수, 단조 시계의 턴별·전체 실행시간을 추가했다.
- 자체 화면 관측 함수, 목록·필터 및 폼·복구 대조 예제, 제품 소개 장면의 선택 도구 지침을 동봉했다. 외부 스킬 코드·훅은 복제하거나 설치하지 않았다.

## 소요시간 관련 변경

| 이전 계약 | 0.14.0 계약 |
|---|---|
| 모드 질문으로 시작하거나 넓은 인벤토리부터 수행 | 기본 핵심 모드, 대상과 필요한 의존 자산부터 단계적으로 확인 |
| 핵심 모드도 전략 스케치 3안 | 추천 1안, 선택에 도움이 될 때만 비교 1안. 명시한 개수·전체 모드는 보존 |
| 작은 작업도 단계별 문서·위임·반복 규칙을 적용할 수 있음 | 단일 오케스트레이터·간결한 로그·필요한 단계만 사용 |
| 대표 컷 2~3장과 광범위한 검수 참조 | 대표 상태 하나부터 요청 범위·위험에 따라 추가, 관측과 수정 일괄 처리 |
| 좁은 진단도 하위 읽기 지도가 문서 전체를 다시 요구 | 과업·검수 범위별 절만 읽고 같은 세션의 변경 없는 규칙은 재사용 |
| 제작과 검수의 수정 루프가 누적될 수 있음 | 하나의 총 수정 예산, 최종 영향 범위만 재검증 |

위 표는 실제로 바꾼 실행 계약이다. 모델을 사용한 전후 전체 작업시간 비교는 하지 않았으므로 속도 향상률을 주장하지 않는다. 평가의 elapsed_seconds는 스크립트 실행시간이며 실제 사람의 응답 대기시간이나 제품 제작시간 전체와 다르다.

## 실행 검증

| 검사 | 관찰한 결과 | 판정 범위 |
|---|---|---|
| 기존 기준선 | 76개 테스트 통과 | 변경 전 저장소 상태 |
| 최종 단위·계약 검사 | 136개 중 실패 0·오류 0, 브라우저 통합 클래스 1개 별도 실행으로 건너뜀. 로컬 검사 본체 약 3.3초 | Python 평가 동작·문서 계약·패키지 호환·링크 |
| 별도 실제 Chrome 통합 | 6개 통과 | DOM 불변·내용/입력값 수집 제외·범위/상한·반복 후보·익명 루트/중복 ID 선택자·필터 유지·오류 복구 |
| 예제 실물 | 390×900 목록, 1280×900 폼 캡처를 직접 열어 확인. 실제 브라우저 뷰포트와 문서 폭 대조 | 두 로컬 예제의 해당 기본 상태. 전체 접근성 인증 아님 |
| 평가 dry-run | 기존 4과제×2모드와 상태 기반 21과제×2모드 모두 명령 생성 성공 | 설정·시나리오 적합성. 실제 모델 성공 아님 |
| JavaScript·메타데이터·로컬 링크 | Node 구문 검사, JSON 파싱, 동봉 문서 링크 확인, git diff --check 통과 | 구조·패키징 |

브라우저 통합은 Node.js 22+와 로컬 Chrome/Chromium에서 `GX_BROWSER_TESTS=1`로 실행한다. 기본 단위 검사에는 브라우저 시작을 포함하지 않는다. 초기 dump-DOM 방식은 Windows에서 종료 대기가 지연되어 테스트 전송을 DevTools 기반 결과 관측으로 바꿨으며, 테스트가 시작한 브라우저 프로세스만 종료한다.

## 독립 검토와 수정

1. 모델이 작성한 invalidated 사유만으로 필수 결정을 지우던 평가 허점을 재현했다. 신뢰할 수 있는 시나리오의 명시적 scope_change 응답이 정확한 ID·유형·범위 버전·사유를 허용한 경우만 일회성으로 처리하도록 고쳤다. 재검토에서 관련 28개 대화 검사와 별도 재현을 통과했다.
2. 익명 루트의 선택자가 범위 밖 요소를 가리키던 관측 도구 문제를 실제 Chrome에서 재현했다. 전역에서 정확히 다시 찾을 수 있는 경로를 만들고 익명 루트·중복 ID 역조회 검사를 추가했다.
3. 정적 BX 크기 검사가 영상 절에 있어 건너뛰어질 수 있던 지침을 공통 절로 이동했다.
4. 좁은 작업의 빠른 경로가 하위 UI·AI 표현·완성도 문서에서 전체 읽기로 되돌아가던 규칙을 범위별로 정리했다. 마지막 재검토에서 필수 증거·회귀·최종 버전 기준이 유지됨을 확인했다.

## 한계

문서 계약 검사는 실제 모델이 모든 상황에서 지침을 지킨다는 증거가 아니다. 모의 CLI 이벤트 검사는 평가 러너의 동작을 검증하며 실제 제품 품질을 검증하지 않는다. 21개 모델 인수 과제는 실행 가능한 입력과 확인 기준을 준비한 상태로, 실제 모델 반복 실험·두 호스트 장기 사용성·정량 속도 향상은 미측정이다. 경량 실행에서도 필수 의도 확인·응답 대기·요청한 과업과 최종 수용 기준은 유지한다.
