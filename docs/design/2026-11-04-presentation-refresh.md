# GX Design 소개·문서·제품 페이지 개선

2026-11-04. 기준: main `54e936b`, 공개 Pages의 배포 원본 `gh-pages` `b36cb397`. 설명·문서 변경의 준비 버전은 0.14.1이다.

## 요청과 확정 방향

사용자는 긴 플러그인·스킬 설명과 README를 간결하고 전문적인 용어로 개선하고, GitHub Pages에 gx-redesign을 적용하도록 요청했다. 페이지 방향 질문에 **제품 소개형으로 재구성: 활용 사례와 결과물을 먼저 보여주고 설치로 연결**을 선택했다.

- 대상: 처음 방문한 개발자·기획자·디자이너와 기존 설치 사용자.
- 목표: 지원하는 디자인 작업, 받을 수 있는 결과물, 새 제작과 기존 개선의 구분, 설치·첫 요청을 빠르게 이해한다.
- 유지: GX Design 제품명과 명령 식별자, 두 호스트 지원, 실제 기능·권한 계약, 기존 사례 PNG와 before/after 의미, 인디고·네이비·밝은 배경의 브랜드 팔레트.
- 변경: 공개 소개 문구·제목, README 정보 순서, 제품 페이지 정보 구조·레이아웃·상호작용·반응형 표현.
- 범위 제외: 디자인 파이프라인의 동작 변경, 새 기능·외부 런타임 의존성, 미측정 속도·전환·품질 수치.

공통 제품 소개: **브랜드·그래픽·UX/UI·영상의 기획, 제작, 개선과 품질 검토를 지원하는 디자인 워크플로.**

### 사례 이미지 전후 관계 정정

사용자가 기존 PNG 파일명이 반대로 붙어 있었다고 직접 정정했다. **초록색·어두운 대시보드가 개선 전, 흰 바탕의 조회 화면이 개선 후**다. 이전 파일명과 기존 설명을 신뢰해 반대로 소개했던 내용은 유지하지 않는다.

- 개선 전: `site/assets/redesign-before-dark.png` — 기존 `redesign-after.png`의 원본 바이트.
- 개선 후: `site/assets/redesign-after-light.png` — 기존 `redesign-before.png`의 원본 바이트.
- 정본: `site/assets/redesign-case.json`에 사용자 확인 근거·치수·원본 SHA-256을 기록한다. README·페이지·공유 이미지·대체 텍스트·검사 모두 같은 관계를 사용한다.
- 원래 파일명의 애매한 경로는 제거한다. 검사는 사용자 확인 이미지의 해시까지 대조해 같은 이름 아래 전후가 다시 뒤집히는 경우를 막는다.
- 초기 `deployed-before-*`·`after-*` 캡처는 이 정정 전의 잘못된 라벨을 포함한 역사 자료다. 최종 판정은 정정된 이미지·설명을 다시 캡처한 결과만 사용한다.

## 진단과 수용 기준

진단은 공개 배포 원본을 로컬 Chrome에서 1440×1000, 390×844로 관찰하고 관련 원본을 대조했다. 공개 URL은 HTTP 200을 확인했지만 웹 열람 도구와 직접 Chrome 원격 탐색은 실패했다. 비교 캡처는 배포 원본의 로컬 복사본이며 외부 글꼴 CDN을 차단한 시스템 대체 글꼴 상태다. 이를 공개 페이지의 글꼴·네트워크 성능 검증으로 확대하지 않는다.

## 구현·검증 기록

- 메타데이터·여섯 스킬·세 역할의 공개 소개와 README를 정리했다. 식별자·호출·모델·도구·소개 이후 본문 계약은 유지했다.
- 기존 전문 용어보다 옛 홍보 문장·제목·설치 블록 개수에 의존하던 검사는 기능 계약 기준으로 조정한다. 새 문구를 그대로 맞히는 검사는 추가하지 않는다.
- 실제 캡처·원시 관측·실행 로그는 gitignore 대상 `outputs/validation/`에 남긴다. 최종 산출물 해시와 실행 결과는 검증 완료 후 이 기록에 추가한다.
- Pages는 `main/site/`와 별도인 `gh-pages:/`에서 제공된다. main의 변경만으로 공개 사이트가 갱신됐다고 보고하지 않는다.

## 최종 검증

- 등록 설명은 기존 182자에서 51자로 정리했다. 마켓플레이스·Claude·Codex·README는 같은 제품 범위를 설명한다. 독립 편집 검토에서 기능 과장·진입 경계·설치 정보·출처 누락은 발견하지 못했다.
- Windows Python 3.10.11, Node 22.14.0, 로컬 Chrome에서 `GX_BROWSER_TESTS=1 python -m unittest discover -s tests -v`: **178개 통과, 실패·오류·생략 0, 28.878초**. 이는 검사 실행 시간이며 제품 제작 소요시간이 아니다.
- 최종 HTML SHA-256: `86eca7a1834d5ed3605912c508b30ea4e991de93365ee595ec51531713ed0b8b`. `corrected-desktop/mobile` 캡처와 관측 JSON은 이 버전에 연결한다.
- 사이트 실행 점검 **18개 통과**: 두 호스트 명령, 탭 초기 상태·화살표/Home/End·포커스, 복사 성공·중복 방지·거절·대체 복사, 320/360/390/768/1440 CSS 폭, 720 CSS 폭/DPR 2의 200% 상당 재배치, 모션 감소, 주 설치 링크, JavaScript 미사용 시 두 설치 명령 접근.
- 클립보드는 제어된 API 어댑터로 성공·실패·대체 경로를 검증했다. 운영체제 클립보드는 읽거나 변경하지 않았으며 실제 HTTPS 권한 UI를 실행했다고 주장하지 않는다. 확대 조건도 브라우저 도구모음의 실제 확대와 구분한다.
- 독립 축 B가 정정된 캡처 4개와 원본·정본 JSON을 대조했다. 초록색 BEFORE·흰색 AFTER, 사례 설명·원본 경로·대체 텍스트·비율·읽힘·배치에 새 이슈 없음. 이전 사진 관계를 전제로 한 판정은 이 결과로 대체한다.
- 축 A/C는 선택한 제품 소개 방향, 명령·브랜드 팔레트·원본 자산 보존, 사례 우선 배치, 설치 접근과 전후 관계 정정을 기준으로 확인했다. 정성적 선호·사용자 이해도·전환율 향상의 실측을 주장하지 않는다.

### 검사 실행부 보강

전체 검사 중 기존 Windows 강제 종료 검사의 Chrome 파일 잠금이 재현됐다. 기존 파일은 기준 커밋과 같았으며 소개 페이지 변경에 따른 실패가 아니었다. 3개 동시 실행 중 2개가 실패했고 `taskkill /T` 자체의 시간 초과와 남은 자손의 파일 잠금을 확인했다.

테스트 런처의 Windows 분기에 기존 평가 러너의 Job Object 관리 함수를 재사용했다. 확정 파일 경로로 로드해 동명 외부 패키지의 영향을 피하고, 종료 확인 뒤 프로필을 정리한다. 기존 stdout/stderr bytes·TimeoutExpired 계약과 POSIX 분기는 유지했다. 수정 후 준비 확인을 포함한 3개 동시 스트레스가 모두 통과했고, 브라우저 13개·평가 종료 회귀 19개도 통과했다. 공용 모듈 추출 대신 private helper를 재사용한 한계와 고부하에서 기존 5초 시작 시간이 짧을 수 있는 한계는 남는다.

로컬 미리보기 서버의 백그라운드 실행은 자동 승인 검토가 정책상 거부해 사용하지 않았다. 브라우저 검증은 별도 서버 없이 파일로 완료했다. 검사자가 만든 일부 임시 폴더도 재귀 삭제가 정책상 거부되어 남겼으며 우회 삭제하지 않았다. 소유 브라우저 프로세스 잔존은 0개로 확인했다. 이 임시 자료는 PR에 포함하지 않는다.
