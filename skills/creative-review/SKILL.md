# Creative Review Skill

## 목적

완성된 결과물이 단순히 보기 좋은 수준을 넘어 프로젝트 목표와 전략을 충족하는지 검수한다.

## 공통 검수 기준

### 목표 적합성

- 프로젝트 목표를 충족하는가?
- 타깃 사용자에게 적절한가?
- 핵심 메시지가 명확한가?

### 전략 일치성

- 승인된 전략과 일치하는가?
- 핵심 인사이트가 결과물에 반영되었는가?
- 차별화 방향이 드러나는가?
- (레퍼런스 입력을 쓴 경우) 산출물의 레퍼런스 근접도가 요청한 다이얼값과 맞는가? (REFERENCE-DRIVEN §2)
- (레퍼런스 입력을 쓴 경우) 저작권 가드 위반 0건인가 — 워드마크·letterform·유명 시그니처 재현 없음? (REFERENCE-DRIVEN §4)

### 정보 구조

- 정보 우선순위가 명확한가?
- 불필요한 요소가 있는가?
- 사용자가 다음 행동을 이해할 수 있는가?

### 시각 완성도

- 위계가 명확한가?
- 레이아웃과 간격이 일관적인가?
- 컬러와 타이포그래피가 체계적인가?
- 이미지 스타일이 일관적인가?
- (UI·그래픽·코드 렌더) 안티-슬롭 — AI 기본 룩 4종을 무심코 답습하지 않았는가? (VISUAL-CRAFT §1)
- (UI·그래픽·코드 렌더) 일관성 잠금 — accent·radius 체계·라이트/다크가 각각 하나로 고정됐는가? (VISUAL-CRAFT §3)
- (UI 모션) [MOTION.md](../gx-design/MOTION.md) §A를 지키는가 — 사용 빈도에 비해 과한 모션은 없는가, ease-in을 쓰지 않았는가, 인터랙션이 300ms 이하인가(모달·드로어·마케팅 연출 예외), transform·opacity만 움직이는가, reduced-motion에서 모션을 끄는 대신 "덜" 움직이는가? 모션 지적은 MOTION §C 표(`요소·위치 | Before | After | Why`)로 쓴다.
- (UI·그래픽·코드 렌더·Gemini 웹 생성) 요소·카피 텔 — [ANTI-TELL-CHECKLIST.md](../gx-design/ANTI-TELL-CHECKLIST.md) 항목을 위반하지 않았는가? 근거 기록 없는 위반은 Major 이상.
- (코드 렌더) detect 출력이 첨부됐으면 — 실제 확인된 문제의 사용자 영향에 따라 심각도를 판정하고, advisory는 참고한다. CLI 실행 실패는 검증 제약으로 기록하고 수동 점검 근거를 확인한다. 브리프가 의도한 선택을 기계가 지적한 경우 기각 사유가 기록됐는지 확인한다.

### 생성·렌더 실물 (실물 이미지가 있는 경우)

- 실물 이미지를 직접 열어 확인했는가?
- AI 아티팩트나 렌더 결함이 없는가? (깨진 글자, 왜곡, 폰트 폴백 흔적)
- 기술 규격이 정확한가? (치수, 해상도, 컬러 값)
- 구성 문제가 없는가? (잘림, 오버랩, 여백 불균형)
- 다른 자산과 스타일이 일관적인가?
- 산출물이 의도와 다른 것으로 읽히지 않는가? (정체성 오독)

### UX/UI

UX/UI 진단·검수는 [UI-QUALITY.md](../gx-design/UI-QUALITY.md) §2~4를 읽는다. 축 B 보고 안에서 시각·UX 비평과 구현 점검을 구분하고, 화면 목적·핵심 과업에 따른 사용자 영향과 증거 상태(확인/추정/미검증)를 기록한다. 명세 검토와 실제 조작 검증을 구분하며, 해당 없는 테마·플랫폼을 요구하지 않는다.

- 화면 위치 인지·다음/이전 단계·라벨 일관성·막다른 길·핵심 과업까지 단계 수가 화면 목적에 맞는가? (UI-QUALITY §1 IA·과업 흐름 점검표)
- 핵심 과업이 효율적인가?
- 상태와 피드백이 명확한가?
- 오류와 예외 상황을 고려했는가?
- 접근성과 반응형을 고려했는가? 실행 가능한 UI면 접근성 실행 체크(UI-QUALITY §4)와 위험 기반 폭 선택·여정 로그(VISUAL-QUALITY)가 기록됐는가?
- 결론마다 그 증거 종류가 뒷받침할 수 있는 범위 안에서 주장했는가(UI-QUALITY §2 증거 종류별 주장 허용표)? 사용자 자료가 없는 사용자 영향 서술에 `휴리스틱 추정`이 표기됐는가?
- 행동·오류·복구 문구가 실제 기능과 일치하고, 관련 긴 텍스트·입력 보존·빈 상태·권한·재시도 조건이 명세와 실물에 반영됐는가?
- 디자인 자료 검색을 썼다면 후보의 목적·플랫폼·브랜드 적합성 및 채택 근거가 있고, 폰트·색·상호작용의 미검증 조건을 명시했는가?

### 영상

- 초반에 관심을 확보하는가?
- 메시지 흐름이 자연스러운가?
- 장면과 내레이션이 중복되지 않는가?
- 자막의 가독성과 노출 시간이 적절한가?
- 러닝타임에 불필요한 장면이 없는가?
- (모션·영상 — [MOTION.md](../gx-design/MOTION.md) §B) fps가 고정되고 씬 합이 러닝타임과 프레임 단위로 맞는가? (B1)
- 화면 텍스트마다 등장 후 정지 홀드가 명세·실물에 있는가? (B2)
- 첫 1~3초에 핵심 메시지 또는 시각 사건이 있는가? (B5)
- 자막·CTA·로고가 게시 플랫폼의 안전영역 안에 있고, 플랫폼 UI가 덮는 영역을 피했는가? (B6)
- 렌더 실물이 있으면 컨택트 시트·핵심 구간 프리뷰로 확인했는가? (VISUAL-QUALITY 영상 분기)

### 제작 가능성

- 실제 제작 가능한 수준인가?
- 필수 규격이 포함되어 있는가?
- 파일 및 결과물 구조가 명확한가?
- 추가 결정이 필요한 부분이 표시되어 있는가?
- 명세의 수용 체크(Acceptance Checks) 조건을 실제로 충족하는가? (creative-production 수용 체크 항목 대조 — 미충족은 Critical/Major로 분류)

### 개선 목표 달성 (리디자인 축 C)

gx-redesign 단계 5의 축 C는 아래 두 표로 판정한다. 입력은 개선 브리프의 성공 기준 표([REDESIGN-INTERVIEW.md](../gx-redesign/REDESIGN-INTERVIEW.md)), 진단표(진단 ID), 제작 변경 기록, 검수 대상 실물이다.

**1. 성공 기준 재측정** — 기준 ID마다 브리프에 적힌 **같은 관찰법**(같은 폭·경로 ID·도구·조건)으로 재측정해 `결과` 열을 채운다.

| 기준 ID | 기준선 | 목표값/관찰법 | 재측정 값·증거 | 결과 |
|---|---|---|---|---|
| G-01 | 담기 불가(J-01-375) | J-01-375 담기 완료 · 4단계 이하 | J-01-375 4단계 완료, 여정 로그 경로 | 달성 |

- 결과는 `달성 / 미달 / 미검증(사유) / 출시 후 측정 / 정성 기준 — 사용자 확인 필요` 중 하나다.
- 관찰법을 바꿔 측정한 값은 `비교 불가`로 적고 달성 근거로 쓰지 않는다. 기준선이 `미측정`이면 개선 폭을 주장하지 않고 재측정 값만 보고한다.
- 증거 수준은 [UI-QUALITY.md](../gx-design/UI-QUALITY.md) §2 증거 종류별 주장 허용표를 따른다 — 캡처만으로 조작 과업의 달성을 판정하지 않는다.
- polish 경로처럼 성공 기준 표가 없으면 선택된 진단 ID마다 진단표의 관찰 증거를 같은 방법으로 재확인한다.

**2. 변경 추적** — 변경 기록(before → after → 근거)의 행마다 변경 ID(예: CH-01)를 연결한다. 변경 기록에 ID가 없으면 검수가 행 순서대로 부여하고 그 사실을 적는다.

| 변경 ID | 진단/목표 ID | 검수 결과 |
|---|---|---|
| CH-01 하단 바를 옵션 시트 열림 시 숨김 | D-03 → G-01 | 해소 — J-01-375 재실행 통과 |
| CH-02 히어로 배경 그라디언트 교체 | (연결 없음) | 근거 없는 변경 — 제작으로 되돌림 |

- 진단/목표 ID에 연결되지 않는 변경은 근거 없는 변경으로 처리한다.
- 수정 범위에 선택된 진단 ID 중 대응 변경이 없거나 재확인에서 남아 있으면 `미해소`로 적는다.
- 같은 경로 ID·폭으로 회귀를 확인하고, 진단되지 않은 새 결함은 별도 행으로 적는다.

## 검수 결과 형식

1. 총평
2. 잘된 점
3. Critical Issues
4. Major Issues
5. Minor Issues
6. 수정 권장사항
7. 수정 우선순위
8. 최종 승인 여부

리디자인 축 C 보고는 1. 총평 안에 성공 기준 재측정 표와 변경 추적 표를 넣는다.
