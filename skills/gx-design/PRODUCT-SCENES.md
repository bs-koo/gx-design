# 제품 소개 장면 — 선택 제작 경로

제품 화면 일러스트·기능 소개 카드·커서 데모를 요청했을 때만 읽는다. 프로젝트 전체가 아니라 영역별로 사용 목적·실제 동작/연출·파일 형식을 구분한다. 랜딩 안의 실제 CTA·폼은 UI 검증 대상이고 히어로 커서는 연출일 수 있다.

1. 브리프에서 정해진 메시지·배치 크기·브랜드·결과물 형식을 재사용한다. 새로 필요한 필수 결정만 질문하고 관련 작업은 답변을 기다린다.
2. 제품의 기존 컴포넌트와 허용된 예제로 시작한다. 가장 가까운 구도·상태를 고르고 제품 토큰·콘텐츠에 맞춘다. 정답 외형을 복제하지 않는다.
3. 실제 표시 크기의 스틸에서 구도·위계·밀도를 먼저 확인한 뒤 메시지에 필요한 모션을 작성한다. 작은 폭은 단순 축소 대신 읽히는 구도로 조정한다.
4. 필요한 시작·중간·종료·루프 연결 프레임과 관련 폭을 확인한다. 모션 감소·정적 대체는 노출 환경과 합의한 조건에 따른다. 최종 파일·관측 조건을 검수 근거에 연결한다.
5. 연출된 클릭은 기능 검증으로 세지 않는다. 실제 버튼·폼은 원본에서 별도 실행하고 미검증은 구분한다. 수정·최종 검수 예산은 [RUN-BUDGET.md](RUN-BUDGET.md)를 공유한다.

## 선택 도구와 경계

- [Stageshow](https://github.com/benjitaylor/skills/tree/802057409787133703c56001080169e347305572/stageshow): 설치·권한이 제공된 경우 좋은 예제·React kit·촬영 도구를 선택 활용한다. 없으면 기존 스택과 브라우저·렌더 수단을 사용한다. 서드파티 앱 아이콘·상표는 소스의 MIT와 별도 조건임을 확인한다.
- [Agentation](https://www.agentation.com/): 기존 설치가 있으면 피드백 위치를 D/CH ID에 연결한다. 사용자가 지목한 범위를 넘겨 수정하지 않는다. 자동 설치·전역 훅은 하지 않는다.
- [DialKit](https://github.com/joshpuckett/dialkit): 개발 중 값·모션 비교에 활용할 수 있다. 선택된 값은 기존 토큰·소스로 반영하고 개발 패널은 최종 결과물 계약에 따라 제거한다.
- [Swarm Rebuild](https://github.com/DhvanilPatel/swarm-cursors): 기존 페이지가 재구성되는 소개 연출의 후보다. 코드 재사용 조건이 확인되지 않아 GX에 번들하지 않는다. 화면 속 커서 수·진행률을 실제 AI 작업자·작업 로그로 설명하지 않는다.

화면 구조 요약이 필요하면 [references/OBSERVATION.md](references/OBSERVATION.md)의 자체 관측 도구를 사용할 수 있다. 소개 장면 생성만으로 UX 개선·접근성·기능 통과를 주장하지 않는다.
