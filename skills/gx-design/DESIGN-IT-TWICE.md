# 전략 개발 — 필요한 후보 → 선택 → 확장

방향이 열려 있는 신규 작업·전체 리뉴얼 또는 후보 비교 요청에만 읽고 적용한다. 방향·보존 조건이 정해진 제작·부분 수정은 새 후보를 만들지 않고 기존 결정·범위 버전을 재사용한다. 질문·승인 재사용·대기는 [HOST-COMPAT.md](HOST-COMPAT.md), 작업량·승격은 [RUN-BUDGET.md](RUN-BUDGET.md), 전략 산출물 형식은 [design-strategy](../design-strategy/SKILL.md)를 따른다. 공통 계약과 해당 절을 이미 읽었고 바뀌지 않았으면 다시 읽지 않는다.

## 후보 수와 실행 깊이

| 조건 | 만드는 후보 | 선택 전 범위 |
|---|---|---|
| 핵심 모드의 열린 방향 | 목표·제약에 근거한 추천 스케치 1안. 실제 경쟁하는 방향을 비교해야 할 때만 실질적으로 다른 비교 1안 추가 | 각 10~15줄, 필요한 대표 영역·핵심 상태 |
| 전체 모드·명시적 3안 요청 | 철학이 다른 스케치 3안 | 각 10~15줄, 필요한 대표 영역·핵심 상태 |
| 방향이 이미 확정된 제작·부분 수정 | 새 후보 없음 | 기존 선택·근거·적용 범위 재사용 |

비교 1안은 목표 달성 방식·개입 범위·정보 구조처럼 결과를 바꾸는 선택이 실제로 경쟁할 때 쓴다. 팔레트·장식만 바꾼 미니 대안으로 수를 채우지 않는다. 비교가 불필요한 추천 1안도 새 핵심 방향이므로, 사용자의 기존 위임이 없으면 방향 확정까지 기다린다. 전체 모드를 요청하지 않았다는 이유만으로 필수 의도를 생략하지 않는다. 요청이 후보 2개 등 수를 명시하면 그 수를 존중한다.

세 안이 필요한 경우의 철학 예시(매체·과업에 맞게 조정):

- A안 — 본질 우선: 핵심 문제 하나를 가장 적은 요소로 해결
- B안 — 차별화 우선: 경쟁 지형의 빈 위치를 점유
- C안 — 시스템 우선: 확장·반복 운영을 전제로 설계

리디자인의 최소 개입·리프레시·리뉴얼도 같은 원리로 사용한다. 핵심 모드에서는 목표·제약에 맞는 철학부터 선택하고 경쟁하는 철학만 비교한다. 세 철학을 모두 작성해야 시작할 수 있는 절차로 쓰지 않는다.

## 절차

1. **입력 확인**: 확정 브리프 또는 기존 기록에서 목표·타깃·결과물·보존 조건·관련 진단/목표 ID를 가져온다. 방향이 정해졌으면 아래 후보 생성을 생략하고 선택 재사용 근거만 기록한다. 새 의존 작업을 시작하기 전 미해결 필수 결정이 없는지 확인한다.
2. **스케치**: 핵심 모드는 한 주체가 위 표의 필요한 후보만 작성한다. 전체 모드는 위임이 허용되고 도구가 있으며 역할 분리의 실익이 있을 때 세 전략 역할에 입력 11항목·범위 버전·각 철학을 전달할 수 있다. 위임할 수 없으면 주 에이전트가 필요한 후보를 순서대로 같은 계약으로 작성한다. 각 스케치는 한 줄 콘셉트 / 해결 문제(리디자인은 진단 ID) / 구조 요지 / 핵심 리스크 / 피할 표현을 담는다. UI·그래픽은 VARIANCE·MOTION·DENSITY와 근거를 내부 기록에 남긴다.
3. **판정 가능성 확인**: 시각 비교가 필요하면 대표 영역·핵심 상태만 작게 만든다. 선택 전 통합·전체 확장은 하지 않는다. 복수 후보는 과업 해결 방식의 실질 차이를 확인한다. hard 톤 기준·유지 자산으로 공유되는 팔레트·구조를 억지로 바꾸지 않는다. soft 이탈은 근거를 기록한다([DESIGN-TONE-ANCHOR.md](DESIGN-TONE-ANCHOR.md)).
4. **추천·선택**: 적합성·실행 가능성·리스크와 선택에 따른 결과 차이를 설명한다. 근거 있는 추천만 제시하고 자유 응답·거절도 유효하게 처리한다. 이미 선택·위임이 있으면 그 범위에서 재사용한다. 새 필수 선택이 남았으면 의존 제작·파일 변경·위임은 중단하고, 부분 답변은 해당 결정만 확정한다.
5. **모션 범위**: 모션이 있고 허용 범위가 결과를 바꾸는 미확정 결정일 때만 독립 문항으로 묻는다. UI는 피드백·진입·스크롤, 영상은 컷 편집·키네틱 타이포·풀 모션 등 매체에 맞는 결과 차이를 설명한다. 내부 다이얼 숫자를 첫 선택지로 내세우지 않는다. 정해진 범위는 재질문하지 않으며 실제 필요한 경우만 [MOTION.md](MOTION.md)의 해당 절을 읽는다.
6. **확장**: 확정된 1안만 design-strategy의 콘셉트 형식으로 확장하고 폐기안은 스케치로 남긴다. 철학·다이얼·보존 조건을 유지한다. 변경이 필요하면 근거·범위 버전·영향 결정을 갱신하고, 승인·위임 범위를 벗어나면 그 결정과 의존 확장을 기다린다. 다른 안의 확장은 사용자 요청이 있을 때만 추가한다.
7. **기록**: 후보·선택·위임 또는 재사용 근거, 적용 범위·버전, 관련 진단/목표 ID, 확정 다이얼·모션 범위, 확장 경로를 outputs/strategy/ 또는 해당 작업의 기존 기록에 남긴다. 모든 후보를 거절하면 거절 이유와 실제 미해결 결정을 확인하고 RUN-BUDGET의 해당 단계 승격 규칙을 적용한다. 한 번의 거절로 전체 흐름을 처음부터 다시 열지 않는다.
