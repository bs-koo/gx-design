# 전략 N안 개발 — Design It Twice (스케치 → 선택 → 확장)

목표: 서로 **전략적으로** 다른 콘셉트를 만들고, 비교와 소신 추천을 거쳐 사용자가 선택하게 한다.
"표현만 다른 같은 전략" 3개는 실패다 — 철학이 달라야 한다.
세 안을 모두 완성 형식으로 쓰지 않는다. 발산은 **스케치 3안**에서, 깊이는 선택된 1안의 **확장**에서 얻는다. 이 절차는 전체·핵심 모드 공통이다(작업량 수치는 [RUN-BUDGET.md](RUN-BUDGET.md)).
실행 전 [HOST-COMPAT.md](HOST-COMPAT.md)의 위임 규칙과 [design-strategy 스킬](../design-strategy/SKILL.md)의 역할·산출물 계약을 읽는다.

## 절차

1. **스케치 실행 주체**: 전체 모드에서 위임이 허용되고 서브에이전트 도구가 있으면 전략 역할 3개에 브리프 경로, 리서치 경로, 위임 11항목, 배정 철학을 동일하게 전달해 스케치를 독립 작성한다(병렬 가능). 위임할 수 없으면 주 에이전트가 같은 입력과 design-strategy 역할·산출물 계약을 사용해 세 스케치를 순서대로 각각 쓴다. 핵심 모드는 한 주체(전략 역할 1개 또는 주 에이전트)가 세 스케치를 순서대로 쓴다.
2. 각 안에 서로 다른 철학을 배정한다(매체에 맞게 문구 조정):
   - **A안 — 본질 우선**: 타깃의 핵심 문제 하나를 가장 적은 요소로 해결하는 방향
   - **B안 — 차별화 우선**: 경쟁 지형의 빈 위치를 점유하는 반대 포지션
   - **C안 — 시스템 우선**: 확장·반복 운영을 전제로 한 플랫폼적 접근
3. 각 안을 **10~15줄 스케치**로 outputs/strategy/에 저장한다(design-strategy의 스케치 형식). 항목:
   - 한 줄 콘셉트
   - 해결하는 문제(리디자인은 진단 ID)
   - 구조 요지
   - 다이얼 VARIANCE·MOTION·DENSITY 3값(1~10) + 한 줄 근거 — UI·그래픽 산출물일 때([VISUAL-CRAFT.md](VISUAL-CRAFT.md) §2 레벨 정의, 기본값은 화면 목적에서 도출)
   - 모션 범위 제안(모션이 있을 때)
   - 핵심 리스크
   - 부정 정의 1줄: `not X, not Y`
   다이얼은 사용자에게 숫자로 따로 묻지 않는다 — **안 선택이 곧 다이얼 확정**이다.
4. **발산 점검**: 두 안이 같은 팔레트나 같은 레이아웃 원형(예: 히어로+3열 카드)을 공유하면 그중 한 안을 배정 철학대로 다시 쓴다. 세 안의 다이얼이 같은 값이면 철학 차이를 다시 확인한다. 디자인 톤 기준이 있으면 팔레트는 공유 제약이므로 콘셉트·구조로 차이를 낸다.
5. 비교표를 만든다. 축: 브리프 적합 / 차별성 / 실행 가능성 / 리스크. 소신 추천 1안을 정하고 근거를 쓴다 — 무관심한 나열이 아니라 확신을 제시한다.
6. 세 스케치와 추천 근거를 보여 준 뒤 [HOST-COMPAT.md](HOST-COMPAT.md)의 질문·선택에 따라 전략 선택을 받는다. 이미 선택이 있으면 다시 묻지 않는다.
   다이얼 값은 호스트가 시각 미리보기를 지원하면 선택지 미리보기에, 지원하지 않으면 선택지 설명에 `VARIANCE 3 · MOTION 2 · DENSITY 7 — 업무 수행 화면` 형태로 표기한다.
   산출물에 모션이 있으면(UI 인터랙션·영상·모션 그래픽) 같은 게이트에 **모션 범위** 문항을 붙인다 — 옵션 3개, 첫 옵션은 화면 목적 기반 추천에 "(추천)" 표기:
   - UI: 피드백만(hover·press) / 진입 연출 / 스크롤 연출
   - 영상: 정적+컷 편집 / 키네틱 타이포 / 풀 모션 그래픽
   모션 범위는 선택된 안의 MOTION 다이얼과 맞춘다(어긋나면 선택 기록에 조정 근거를 남긴다). 모션이 없는 산출물이면 묻지 않는다. 규칙 상세는 [MOTION.md](MOTION.md).
   사용자가 세 스케치를 모두 거절하면 [RUN-BUDGET.md](RUN-BUDGET.md)의 단계별 승격에 따라 스케치를 다시 쓴다.
7. **확장**: 선택된 1안만 design-strategy 콘셉트 작성 형식 전체(Concept Name ~ Risks)로 확장해 outputs/strategy/에 저장한다. 확장은 1회이며, 스케치의 철학·다이얼·부정 정의를 바꾸지 않는다(바꿔야 하면 근거를 선택 기록에 남긴다). 폐기안은 스케치로만 남긴다. 사용자가 다른 안도 확장해 보고 싶다고 하면 그 안만 추가 확장한다.
8. 선택 결과·근거·확정된 다이얼·모션 범위·확장 문서 경로를 outputs/strategy/에 선택 기록으로 저장하고 단계 3으로 간다.
