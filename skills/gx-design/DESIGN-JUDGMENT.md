# DESIGN-JUDGMENT — 목적과 정보 관계에서 출발하는 디자인 판단

UI·웹 화면과 정보 전달 중심 그래픽의 제작·진단·검수에 적용한다. 로고 조형이나 영상 편집에 UI 규칙을 일괄 적용하지 않는다.
Madia Designer의 공개 설명·챕터·전사 일부에서 확인한 관점을 재서술하고 gx 실행 절차로 구성했다. 아래 순서는 gx의 운영 방식이며 제작자의 고정 작업 순서나 사고 전체를 재현한다는 뜻은 아니다.
근거와 확인 범위는 [madia-evidence.md](references/madia-evidence.md)에 있다. 출처 설명·근거 갱신 때 읽고, 일반 제작에는 이 문서만 읽는다. 영상 시청·외부 서비스·유료 강의는 실행 의존성이 아니다.

## 기준과 관찰

- 브리프의 목적·타깃·성공 조건, 유지 자산, 기존 디자인 시스템, 접근성과 플랫폼 제약을 판단의 입력으로 삼는다.
- 색·폰트·간격·모션의 세부 정본은 [VISUAL-CRAFT.md](VISUAL-CRAFT.md), 실제 렌더 확인은 [VISUAL-QUALITY.md](VISUAL-QUALITY.md)다. 이 문서는 무엇을 먼저 보고 변경 이유를 어떻게 설명할지 보완한다.
- UI의 화면 목적·상태·증거 주장 범위는 [UI-QUALITY.md](UI-QUALITY.md), 진단·목표·상태·여정·변경 ID는 [REVIEW-AXES.md](REVIEW-AXES.md)의 기존 계약을 따른다. 같은 진단표·상태표·실행 로그를 재사용하며 사용자 영향 가설은 `휴리스틱 추정`으로 표시한다.
- Claude Code와 Codex 모두 같은 판단과 출력 계약을 사용한다. 파일 읽기·이미지 보기·렌더는 현재 환경의 도구로 수행하고, 도구 부재로 확인하지 못한 것은 한계로 기록한다.
- 화면을 보고 판단한 **관찰**, 사용자에게 미칠 **영향 가설**, 코드·실행·측정으로 확인한 **검증**을 구분한다. 정적 화면의 예상 시선 흐름을 실제 시선 추적이나 사용성 실험 결과로 표현하지 않는다.
- 화면을 보지 못했으면 시각 결함을 확정하지 않는다. 제공된 명세·코드로 가능한 구조 검토를 하고, 확인에 필요한 렌더나 원본을 표시한다. 스크린샷만으로 조작·대비 수치·반응형 통과를 주장하지 않는다.

## 판단 절차

### 1. 사용자가 이해하거나 결정할 대상을 먼저 정한다

화면의 주 과업, 먼저 알아야 할 정보, 다음 행동을 짧게 적는다. 핵심이 상품 비교인지, 가격 확인인지, 읽기인지, 이미지 감상인지에 따라 화면 비중이 달라진다.
필수 정보·정책·상태가 빠졌는지 확인한다. 실제로 필요한 입력·선택·오류·빈 상태·긴 콘텐츠·키보드 등장 등의 케이스를 고른다. 미확정 가격 산식·인증 정책·제품 기능을 시각 정돈을 위해 새로 만들거나 삭제하지 않는다. (근거: M01~M03, M09~M10)

### 2. 화면 전체에서 시선의 경쟁을 찾는다

렌더에서 먼저 눈에 들어오는 제목·이미지·색 면·행동을 찾아 의도한 우선순위와 비교한다. 각각 보기 좋더라도 같은 강도로 경쟁하거나, 전부 비슷해서 핵심을 구분하기 어려울 수 있다.
크기뿐 아니라 면적·굵기·채도·명도 대비·이미지 복잡도·주변 여백을 함께 본다. 강한 배경이 내부 핵심 내용보다 먼저 보이는지도 확인한다. 먼저 보여야 할 대상을 정한 후 주변을 낮출지, 주인공을 키울지 선택한다. (M05, M07, M11, S01~S03, S06)

### 3. 큰 정보 묶음과 내부 관계를 확인한다

상품↔가격·조건, 질문↔답변, 안내↔조작처럼 함께 이해해야 할 대상을 찾는다. 그룹 내부와 그룹 사이의 간격·정렬·배경·테두리가 그 관계를 전달하는지 본다.
한 그룹이 여러 조각으로 읽히거나, 다른 역할이 한 덩어리로 합쳐지는 문제를 구체적인 위치로 지적한다. 카드와 구분선은 필요에 따라 유지·통합·완화한다. 큰 그룹 안의 세부까지 모두 박스로 두르는 방식도 검토한다. (M02~M04, S04~S05, S07)

### 4. 글자·색·이미지의 역할을 실제 콘텐츠로 조절한다

제목·본문·보조정보·행동의 역할에 따라 타이포와 색의 강약을 정한다. 글자 크기만 늘리기보다 중복된 강조, 무거운 굵기, 줄바꿈, 행간과 정렬을 함께 본다.
이미지가 이해·구매·몰입의 주인공이면 피사체·비율·필요한 세부가 가려지거나 찌그러지지 않는지 확인한다. 여러 이미지의 시각적 비중을 맞추되 모두 같은 크기·강도로 만들 필요는 없다.
원본에 없는 정확한 수치를 화면에서 추정해 사실처럼 쓰지 않는다. 픽셀값과 회색 hex는 제품 시스템·실제 배경·뷰포트·언어·접근성 조건에서 정하며, 영상의 예시 값을 모든 제품의 규격으로 고정하지 않는다. (M04~M07, M12, S02~S03, S08~S09)

### 5. 상태와 반복 사용에서도 판단이 유지되는지 본다

정상 화면의 정돈 이후, 필요한 상태에서 의미 구분과 조작 가능성이 유지되는지 확인한다. 예: 채팅 화자와 입력 중 변화, 주문 정보와 합계 관계, 긴 버튼 문구, 모바일 키보드와 주요 행동.
같은 역할은 기존 토큰·컴포넌트를 먼저 사용한다. 정보량이나 상태가 다르다는 이유가 있으면 필요한 변형을 남긴다. 벤치마크는 사용자·과업·콘텐츠·장치가 맞는지 비교하고, 유사한 외형만으로 적합성을 판정하지 않는다. (M01~M03, M08~M10, M13~M14)

### 6. 영향이 큰 변경을 선택하고 반대 효과까지 재확인한다

가장 큰 문제를 해결하는 변경부터 고른다. 주변 강조 완화, 정보 통합, 주인공의 비중 조절, 불필요한 효과 제거 등으로 목적을 회복할 수 있는지 비교한다. 구조나 필수 상태가 잘못됐으면 그 근거에 맞는 구조 수정도 제안한다.
선택한 변경은 유지 자산과 승인된 개선 범위 안에서 수행한다. 변경 후 같은 콘텐츠·뷰포트·상태로 다시 보고, 해결한 문제와 새로 생긴 문제를 함께 확인한다. 장식을 줄일 때 선택·경고·소속·상태를 나타내는 단서가 사라지지 않았는지 확인한다. (M01~M04, M06~M08, S05~S10)

## 조건에 따라 판단이 달라지는 지점

| 선택 | 적용할 이유 | 함께 확인할 반대 효과 | 근거 |
|---|---|---|---|
| 제목·이미지·배너를 크게 | 핵심 메시지·이미지의 전달이나 몰입이 약함 | 상품·필수 정보가 첫 화면 아래로 밀림, 작은 화면에서 과도한 스크롤 | M05, S08, S10~S12 |
| 여백을 늘리기 | 서로 다른 그룹 분리, 읽기와 호흡 확보 | 내용과 무관한 빈 공간, 같은 그룹의 분절, 높은 정보 밀도가 필요한 작업의 비효율 | S04, S07, S13 |
| 카드·배경·구분선 조절 | 정보 소속과 경계를 명확히 표현 | 모든 세부의 박스화, 필수 관계·선택 상태의 소실 | M02~M03, S04~S05 |
| 색과 효과를 절제 | 핵심 정보·행동에 시선을 모음 | 브랜드 표현, 의미 있는 경고·구분, 선택과 피드백까지 약화 | M04, M06, S01, S06, S14 |
| 익숙한 구조·공통 컴포넌트 사용 | 학습 부담과 불필요한 케이스를 줄임 | 현재 과업과 맞지 않는 레퍼런스 복사, 필요한 상태·변형 삭제 | M08~M10, M13~M14 |

이 조건은 일괄적인 미니멀·큰 타이틀·흰 배경·카드 제거 지시로 바꾸지 않는다. 단순함과 시각적 대담함은 브리프의 목적을 달성하는 선택지다.

## 파이프라인별 적용과 기록

- **신규 제작**: 승인된 전략에서 `주 과업 / 우선 정보 → 다음 정보 → 행동 / 정보 묶음 / 필요한 상태`를 정한 뒤 레이아웃·타입·컬러를 선택한다. 기존 제작 명세에 짧게 포함하며 별도 진단표를 만들 필요는 없다.
- **리디자인 진단**: 실제 발견한 문제만 기존 진단 ID와 이슈 형식으로 남기며, 관찰·방해받는 과업·영향 가설·변경 방향·확인 방법을 연결한다. 취향이나 영상 제목은 결함의 근거가 아니다. 심각도는 기존 Critical/Major/Minor 체계와 실제 영향에 따라 정한다.
- **리디자인 제작**: 기존 `변경 ID → before → after → 근거` 표를 유지하고 근거 칸에 진단 ID 또는 승인 목표 ID를 연결한다. 유지 자산·필수 정보·의미 있는 상태를 보존한다.
- **자체 검수·축 B**: 의도한 우선순위와 렌더의 예상 시선 흐름, 묶음, 읽힘을 대조한다. 관련 상태·뷰포트를 확인하고 원래 결함의 해소와 회귀 여부를 보고한다. 변경 이유만 설명하고 실제 결과 확인을 생략하지 않는다.
- 기존 명세·진단표·렌더 품질 로그에 기록한다. 관련 없는 항목의 `해당 없음` 목록이나 같은 보고서를 중복 생성하지 않는다. 실물 미확인은 명세 검토 결과와 분리한다.

기록 예시(가상의 상황): `주 과업=환불 대상 주문 찾기 / 관찰=보조 배너가 주문 상태보다 큰 고채도 면을 차지함 / 영향 가설=필요한 상태를 늦게 찾을 수 있음 / 변경=배너 비중 완화·상태와 주문번호 근접 배치 / 보존=브랜드색·오류 경고 / 확인=같은 화면과 모바일에서 상태·행동의 구분 재점검`.
시각적 정돈만 확인했으면 그 범위로 보고한다. 과업 성공률·전환·만족도 개선은 실제 측정 근거가 있을 때만 확정한다.
