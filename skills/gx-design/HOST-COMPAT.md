# 호스트 호환 실행 규칙

## 읽기 범위와 재사용

이 공통 계약은 변경되지 않은 세션에서는 한 번 읽고 재사용한다. 새 세션·문서 개정·적용 범위 변화가 있을 때 관련 절만 다시 확인한다. 기존에 읽었다는 근거가 없으면 최초 읽기는 생략하지 않는다. 참조 파일 목록을 시작 전 전부 읽는 체크리스트로 사용하지 않는다.

기본은 핵심 모드로 필요한 단계만 실행한다. 사용자가 전체 모드를 명시하면 존중하며, 실제 범위·복잡도가 커졌을 때도 해당 단계만 승격한다. 공통 계약 재사용은 필수 결정 대기나 최종 품질 조건을 생략하는 근거가 아니다. 대상과 필요한 의존 자료부터 읽고 부족한 증거가 있을 때만 점진적으로 범위를 넓힌다. 이미 확인한 파일·정본은 변경되지 않았으면 반복 열람하지 않는다. 검수 독립성·최종 버전 실물 관찰은 REVIEW-AXES의 별도 조건을 따른다.

## 질문·선택

먼저 이해한 목표·유지할 것·만들 결과물·남은 핵심 결정을 짧게 알린다. 내부 모드·frontier·다이얼·문서 이름을 사용자 선택으로 먼저 내세우지 않는다. 요청·파일에서 확인한 사실은 묻지 않고, 이미 확정하거나 위임받은 결정은 해당 범위에서 재사용한다.

실제 제공된 구조적 입력 도구가 있으면 문항 수·선택 방식·응답 형식에 맞춘다. 도구가 없거나 필요한 경로·자유 응답을 담을 수 없으면 모든 선택지를 대화로 제시하고 답변을 기다린다. 도구 제한에 맞추려고 경로를 생략하거나 서로 다른 결정을 합치지 않는다. 일반 대화는 Markdown 번호 질문과 `1A, 2C` 응답 예시를 사용하고 복수 선택은 `1A, 1C`처럼 안내한다. 자유 응답도 유효하다. 구조적 도구가 없는 호스트의 메시지당 최대 4개는 표시 한도이며 질문 총량·라운드 상한이 아니다.

### 질문 작성 기준

- 문항 하나는 결정 하나를 다룬다. 결과를 바꾸는 확인 이유를 한 줄로 설명하고 답에 따른 차이를 보여 준다. 내부 절차 준수 자체를 질문 이유로 삼지 않는다. 필수 문항이면 답변 전 멈출 작업을, 선택적 선호면 답이 없을 때 적용할 기존 기준·제작자 판단을 짧게 알린다.
- 선택지는 결과·비용·보존 범위의 차이를 적는다. 단일/복수 선택을 밝히고 사실 입력에는 억지 객관식을 만들지 않는다.
- 추천은 목표·기존 자산·제약에 근거할 때만 첫 옵션에 `(추천)`과 근거를 붙인다. 근거가 없으면 추천을 만들지 않는다. 매번 첫 옵션을 자동 추천하지 않는다.
- 추천 거절·다른 의견·자유 응답을 의미대로 반영한다. "모름"은 추천 수락이 아니다. 모호함이 필수 결정을 막을 때만 좁혀 묻는다.
- 시각 비교가 필요하고 호스트가 지원하면 미리보기를 쓴다. 지원하지 않으면 텍스트 비교를 제공한다. 브리프 확정 전에는 새 방향의 스케치 대신 기존 자료의 중립적 설명만 쓴다.
- 답변 뒤에는 확정한 내용과 남은 결정을 짧게 알린다.

### 질문 슬롯 산정표

질문 순서의 단일 기준이다. **인터뷰 라운드 규칙은 진행 모드(전체/핵심)와 무관하게 같다.** 사용자 판단이 필요하고 이번 결과를 바꾸는 미확정 결정만 frontier에 올린다. 모든 취향을 질문으로 만들지 않으며, 필수 결정은 frontier가 빌 때까지 필요한 만큼 묻는다. 이미 정해졌거나 사실 수집·인벤토리로 확인된 항목은 건너뛴다.

| 흐름 | 질문할 때 | 우선순위 |
|---|---|---|
| 신규(gx-design) | 결과를 바꾸는 의도가 미정일 때 | 목표·타깃·핵심 문제·매체 중 열린 것 → 범위·제약·유지 기준 → 필요한 하류 결정 |
| 리디자인(gx-redesign) | 변경 범위·유지 조건이 미정일 때 | 개선 목표 → 대상·기기 → 변경 허용 범위·유지 자산 → 필요한 하류 결정 |
| 점검 전용(gx-redesign) | 점검을 막는 정보만 미정일 때 | 점검 대상 → 화면·URL → 기기 → 해당 시 핵심 여정. 모두 확정이면 `[요청에서 확정]`으로 진단 |
| 특정 지적·부분 다듬기 | 대상이나 허용 변경이 미정일 때 | 해당 대상·보존 조건만 확인. 방향·결과물이 정해졌으면 재질문 없이 수정·검증 |

1슬롯은 독립 결정 하나다. 모드와 수정 범위처럼 서로 다른 판단을 한 슬롯에 숨기지 않는다. 관련 질문은 인지 부담에 맞게 묶고, 선행 답변으로 해소된 질문은 제거한다. 내부 모드는 요청 범위로 정하며, 실제 품질·범위·시간의 교환이 있을 때만 결과 중심으로 묻는다. 톤 기준도 사용자가 제약을 이미 명시했다면 재확인하지 않는다. 승인·선택 역시 아래 재사용 규칙을 먼저 적용한다.

## 결정 기록

기존 브리프·선택 기록을 확장하며 별도 정본을 중복 생성하지 않는다. 각 결정에 다음을 남긴다:

| 필드 | 기록 내용 |
|---|---|
| `id` | 안정적인 결정 ID |
| `value` | 현재 값 또는 미정 |
| `status` | 미확정 / 제안됨 / 응답 대기 / 사용자 확정 / 위임됨 / 변경됨 |
| `source` | 근거 발화·자료·도구 응답. 제작자 판단이면 그 사실과 근거 |
| `scope-version` | 적용 대상·허용 범위와 현재 버전 |
| `dependencies` | 이 결정에 의존하는 질문·단계·산출물·위임 |

각 결정이 사용자 판단인지, 자료에서 확인 가능한지, 이미 답했는지, 위임됐는지, 이번 결과를 바꾸는지 먼저 분류한다. 기존 기준 안의 간격·구현 세부는 제작자가 판단한다. 승인·위임 범위를 벗어나는 의미·동작·브랜드·권한 변경이 필요하면 사용자 결정으로 승격한다. 선택적 취향의 `지정 없음`과 `판단 맡김`은 구분한다.

## 답변 게이트

필수 결정을 질문하면 기다리는 결정 ID·범위 버전은 내부 기록에 남기고, 사용자에게는 무엇을 확인하는지와 답변 전 멈출 작업을 짧게 알린다. 내부 ID·버전 표기를 사용자에게 강제하지 않는다. 그 결정에 의존하는 제작·파일 변경·전략 확정·위임은 중단한다. 답변을 기다리는 동안 새 방향의 시안·카피·코드를 만들거나 전략을 전제한 조사를 확대하지 않는다. 허용되는 독립 작업은 지정 자료 읽기·현행 자산 인벤토리·중립적 사실 확인이다. 단순히 "조사"라고 부른다고 독립 작업이 되지는 않는다. 사용자가 명시적으로 다른 작업을 요청한 경우에는 아래 작업 전환 규칙을 적용한다.

| 상황 | 응답 적용과 대기 |
|---|---|
| 비동기 질문 등록만 성공 | 등록은 답변이 아니다. 응답 대기 유지 |
| 빈 응답·시간 경과·창 닫기·취소 | 승인·위임·추천 수락으로 간주하지 않는다. 필수 결정은 대기 유지 |
| 기본 선택 표시·자동 제출 | 기본값을 명시하고 사용자가 확인·제출한 경우만 응답. 도구의 자동 제출은 미응답 |
| 부분 답변 | 답한 결정만 확정하고 나머지 필수 결정은 대기. 관련 의존 작업은 계속 중단 |
| 선택지와 다른 자유 응답 | 의미대로 반영. 필수 값이 모호할 때만 확인 |
| "추천으로" | 현재 지칭한 결정의 추천에만 적용. 여러 추천 중 대상이 모호하면 확인 |
| "나머지는 네가 판단해" | 현재 설명된 작업 범위 안의 위임. 다른 업무·권한까지 확대하지 않음 |
| "그만, 진행해" | 현재 범위의 인터뷰 종료·디자인 판단 위임. 미해결 값·근거는 `[가정]`으로 기록. 기존 금지·보존 조건 유지 |
| "그만"·"멈춰" | 작업 중단으로 처리. 진행 위임으로 해석하지 않음 |
| 예전 질문에 늦은 답 | 결정 ID·범위 버전 대조. 대체된 결정에는 자동 반영하지 않고 현재 결정과의 관계 확인 |
| 대기 중 다른 질문·상태 요청 | 짧게 답하고 원래 필수 결정의 대기는 유지 |
| "그건 나중에, 대신 이것부터" 등 명시적 작업 전환 | 이전 작업의 맥락·미응답은 보류로 보존하고, 이전 결정을 승인·완료·영구 폐기한 것으로 처리하지 않는다. 새 작업이 의존하지 않는 이전 결정의 대기는 새 작업을 막지 않는다. 새 범위의 필수 결정만 확인하고 그 작업의 승인된 범위를 진행 |
| 보류 작업으로 복귀 | 현재 대상·범위와 보류된 결정의 적용 여부를 대조한다. 바뀌거나 모호한 부분만 확인하며 영향 없는 답변·승인은 재사용 |
| 질문 도구 사용 불가 | 대화 질문으로 전환하고 자유 응답 허용. 필수 응답 대기는 유지 |

호스트가 지원하는 대기·재개 방식을 사용하며, 긴 대기 중 불필요한 모델·도구 반복 호출을 하지 않는다. 먼저 실행한 작업자의 결과가 늦게 도착해도 현재 결정 버전과 일치하는지 확인하기 전에는 채택하지 않는다.

선택적 선호는 질문할 때 미응답 시 적용할 기준을 알리고 충분한 응답 기회를 제공하면서 독립 작업을 계속할 수 있다. 여전히 답이 없으면 `지정 없음`으로 기록하고, 알린 기존 기준 또는 승인된 목표 안의 제작자 판단으로 계속한다. **무응답을 사용자 승인·위임으로 기록하지 않는다.** 이 규칙은 필수 결정에 적용하지 않는다.

## 승인 재사용과 변경

요청에서 확정된 결과물·방식·범위와 분명한 실행 의도는 승인 근거로 기록한다. 미정인 필수 결정이 없으면 같은 브리프 승인·실물 제작 여부·이미 보여 준 polish 범위를 다시 묻지 않는다. 예: 모바일·데스크톱 React 화면을 요청했다면 실물 제작 여부를 다시 고르게 하지 않는다. 큰 방향이 열려 있는 신규 작업에는 브리프·대표 방향 선택을 유지한다. 명세·브랜드 가이드·프롬프트만 요청했으면 실물을 자동 추가하지 않는다.

목표·타깃·유지 자산·결과물·게시 대상이 바뀌면 범위 버전을 갱신하고 **영향받는 승인과 산출물만** 변경 상태로 돌린다. 영향 없는 답변·승인은 유지한다. "전략 변경"을 브랜드 보존 해제나 게시 승인으로 확대하지 않는다. 제작 승인은 요청 밖 배포·외부 전송·추가 유료 실행의 허가가 아니며 해당 실행 권한을 따른다. 최종 파일 변경에 따른 검수 무효화·영향 축 재검수는 [REVIEW-AXES.md](REVIEW-AXES.md), 총 수정 예산은 [RUN-BUDGET.md](RUN-BUDGET.md)를 따른다.

## 위임

사용자 또는 프로젝트 지시가 위임을 허용하고 실제 하위 작업자 도구가 있으면 역할, 입력 11항목, 산출 경로, 완료 기준을 명시한다. 결정 기록의 적용 범위·버전과 의존성을 전달하고, 미해결 필수 결정에 의존하는 작업은 위임하지 않는다. 특정 작업자 이름·모델·방식을 자동 전제하지 않는다. 위임 도구가 없으면 주 작업자가 같은 산출물 계약을 따른다.

## 도구 가용성

파일 탐색, 웹 조사, 이미지 열기, 렌더링은 실제 사용 가능한 도구로 수행한다. 제작 경로를 추천하거나 확장하기 전에 현재 도구가 요청한 파일의 생성·편집·내보내기를 지원하는지 확인한다. 도구 이름이나 스킬 설치만으로 제작 가능하다고 판단하지 않는다. 필요한 도구가 없으면 확인하지 못한 사실·관찰 한계와 만들지 못하는 산출물·가능한 대체 납품물의 차이를 먼저 알린다. .pen 파일과 디자인 툴 가이드, 생성 이미지와 프롬프트 문서는 각각 다른 결과물이다. 대체로 납품물·방식이 바뀌면 기존 승인 범위를 확인하고 미확정 필수 결정만 묻는다. 만들지 못한 실물을 문서로 대체해 원래 요청 완료로 보고하지 않는다. 외부 서비스는 사용자 지시와 실행 환경의 권한을 따른다.

## 참조 파일 읽기 실패

스킬 본문이 읽으라고 지정한 참조 파일을 권한·경로·설치 문제로 읽지 못했을 때의 단일 기준이다.

- 그 단계의 절차를 추측·기억·일반 관행으로 대신하지 않는다.

- 실패한 파일 경로와 오류·증상을 보고하고 권한·경로 확인·재설치 등 조치를 안내한다.

- 승인 뒤 의존하는 참조 읽기를 다시 시도하고 실패하면 같은 규칙으로 보고하고 멈춘다.
