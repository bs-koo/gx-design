# 호스트 호환 실행 규칙

## 질문·선택

실제 제공된 구조적 입력 도구가 있으면 그 도구의 문항 수, 필수 선택 방식, 허용되는 응답 형식에 맞춰 질문한다. 한 라운드의 질문은 가능한 한 함께 묻는다. 구조적 질문 도구가 없거나 그 도구의 문항·옵션·선택 방식 제한으로 모든 경로 선택지를 그대로 제시할 수 없으면, 모든 선택지를 빠짐없이 대화에 제시해 묻고 답변을 기다린다. 도구 제한에 맞추려고 경로를 생략하거나 합치지 않는다. 옵션별 시각 미리보기를 제공할 수 없으면 선택지를 텍스트로 적는다. 사용자가 이미 결정을 명시했으면 같은 질문을 반복하지 않는다.

일반 대화에서는 Markdown으로 질문을 번호 매겨 렌더링하고 `1A, 2C` 형식의 답변 예시를 안내한다. 복수 선택은 `1A, 1C`처럼 적게 하고 자유 응답도 허용한다. 구조적 질문 도구가 없는 호스트에서는 메시지당 최대 4개 질문을 제시한다 — 이것은 표시 한도이지 아래 슬롯 예산이 아니다. 더 남은 질문은 다음 묶음도 같은 라운드임을 밝힌다.

### 질문 슬롯 산정표

라운드·질문 수의 단일 기준이다. 각 스킬 문서는 이 표를 참조하고 숫자를 다시 적지 않는다. 슬롯 순서는 우선순위이며, 이미 정해졌거나 사실 수집·인벤토리로 확인된 항목은 건너뛰고 다음 항목이 그 슬롯을 쓴다.

| 흐름 | 전체 모드 | 핵심 모드 |
|---|---|---|
| 신규(gx-design) | 라운드 수 무제한(frontier가 빌 때까지) | 1라운드 4슬롯: [모드 — 인자로 정해졌으면 제외] → 상류(목표·타깃/핵심 문제·매체 중 열린 것) → 톤 기준 첨부 요청 → 피할 것. 핵심 여정은 묻지 않고 `[가정]` |
| 리디자인(gx-redesign) | 라운드 수 무제한(frontier가 빌 때까지) | 1라운드 4슬롯: [모드+범위 결합 1슬롯 — 둘 다 정해졌으면 제외] → 개선 계기·목표 → 대상·기기 → 톤 기준/유지 자산 |
| 점검 전용(gx-redesign) | 1라운드 최대 4슬롯: 점검 대상(복수) → 대상 화면·URL → 기기 → 핵심 여정(여정 점검 시) | 전체 모드와 같다 |

산정 규칙:

- 1슬롯 = 한 번에 답하는 질문 블록 하나다. 모드+범위처럼 결합한 문항은 선택지가 두 축이어도 1슬롯이다.
- 톤 기준 강도 확인(첨부 시)과 게이트 질문(브리프 승인·전략 선택·이어가기·실물 제작)은 예산 밖이다. 요청 해석 카드도 머리말이라 슬롯에 넣지 않는다.
- "메시지당 최대 4개"는 구조적 질문 도구가 없는 호스트의 표시 한도이지 예산이 아니다. 전체 모드의 frontier가 4개를 넘으면 같은 라운드의 다음 묶음으로 나눈다.
- 예산을 넘는 결정은 합리적 기본값으로 채워 `[가정]`으로 기록한다 — 핵심 모드와 점검 전용에서는 2라운드를 열지 않는다.
- 첫 질문 묶음의 결합 슬롯에서 점검 전용이 정해졌으면 점검 전용 행의 슬롯은 그 직후 묶음에 적용한다.

## 답변 게이트

브리프 승인, 전략 선택, 실물 제작 경로처럼 사용자 결정에 따라 결과가 달라지는 단계는 답변을 받은 뒤 진행한다. 이는 확인·선택으로 표현한다. 이미 받은 승인·선택은 유지한다. 결정 전까지 파일 조사와 문서 정리 등 독립 작업은 진행한다. 사용자가 명시적으로 진행을 요청하면 미해결 항목은 [가정]으로 기록한다.

## 위임

사용자 또는 프로젝트 지시가 위임을 허용하고 실제 하위 작업자 도구가 있으면 역할, 입력 11항목, 산출 경로, 완료 기준을 명시해 위임한다. 특정 작업자 이름·모델·방식을 자동으로 주입하거나 전제하지 않는다. 위임 도구가 없으면 주 작업자가 해당 방법으로 수행하고 같은 산출물 계약을 따른다.

## 도구 가용성

파일 탐색, 웹 조사, 이미지 열기, 렌더링은 현재 환경에서 실제로 쓸 수 있는 도구를 확인한 뒤 수행한다. 특정 도구가 없으면 확인하지 못한 사실과 만들지 못한 산출물을 명시하고 가능한 문서·프로젝트 경로를 따른다. 외부 서비스 이용은 사용자 지시와 실행 환경의 권한을 따른다.

## 참조 파일 읽기 실패

스킬 본문이 읽으라고 지정한 참조 파일(BRIEF-INTERVIEW.md, REDESIGN-INTERVIEW.md, 각 단계의 참조 문서)을 권한·경로·설치 문제로 읽지 못했을 때의 단일 기준이다.

- 그 단계의 절차를 추측으로 대신하지 않는다. 기억이나 일반 관행으로 지침을 재구성해 진행하지 않는다.
- 게이트 규칙은 그대로 유지된다. 브리프 승인 전에는 읽기 실패 상태여도 스타일 제안·무드·팔레트·레이아웃·콘셉트를 출력하지 않는다.
- 어떤 파일을 왜 읽지 못했는지(경로와 오류 메시지 또는 증상) 보고하고, 사용자 조치(권한 허용·경로 확인·플러그인 재설치)를 제안한다.
- 그다음 여기서 멈추거나, 스킬 본문(SKILL.md) 단계 0에 적힌 최소 규칙만으로 질문 전용 인터뷰를 계속한다. 질문 전용 인터뷰는 브리프 초안 승인까지만 진행한다.
- 승인 뒤 단계가 같은 파일이나 다른 참조 문서에 의존하면 그 단계에서 다시 읽기를 시도하고, 실패하면 같은 규칙으로 보고하고 멈춘다.
