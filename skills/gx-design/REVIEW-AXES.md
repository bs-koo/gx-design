# 2축 독립 검수

목표: 전략 일치와 완성도를 서로 독립된 눈으로 검수한다.
두 축의 결과는 합치지 않는다 — 한 축의 호평이 다른 축의 결함을 가리지 못하게 한다.

## 절차

1. 전체 모드에서 위임이 허용되고 서브에이전트 도구가 있으면 전략 일치(축 A)와 완성도(축 B)를 분리해 병렬 검수한다. 각 역할은 creative-review 스킬을 읽고 서로의 결과를 보지 않는다. 위임할 수 없으면 주 에이전트가 [creative-review 스킬](../creative-review/SKILL.md)을 읽고 축 A와 축 B를 순서대로 각각 기록한다. 두 보고를 합쳐 결함을 가리지 않는다.
   - **축 A — 전략 일치**: 입력 = 브리프 + 선택된 전략 + 산출물(+ 디자인 톤 기준이 있으면 그 원본 파일, 레퍼런스 입력을 쓴 제작이면 [REFERENCE-DRIVEN.md](REFERENCE-DRIVEN.md) 경로). 검수 범위 = 목표 적합성, 전략 일치성, **디자인 톤 기준 준수**(있을 때 — [DESIGN-TONE-ANCHOR.md](DESIGN-TONE-ANCHOR.md) §4: hard는 근거 없는 이탈이 결함, soft는 이탈의 근거 기록 여부), **레퍼런스 연계**(레퍼런스를 쓴 경우 — REFERENCE-DRIVEN §6: 근접도 다이얼 일치·저작권 가드 위반 0건).
   - **축 B — 완성도**: 입력 = 산출물 + 실물 이미지·렌더 결과 경로(존재 시 필수 — VISUAL-QUALITY.md의 렌더 품질 로그 포함) + 매체 정보 + [ANTI-TELL-CHECKLIST.md](ANTI-TELL-CHECKLIST.md) 경로(UI·그래픽·코드 렌더·Gemini 웹 생성일 때) + [MOTION.md](MOTION.md) 경로(모션이 있는 산출물 — UI 인터랙션은 §A, 영상·모션 그래픽은 §B). 검수 범위 = 정보 구조, 시각 완성도(실물 이미지를 직접 열어 확인, 요소·카피 텔 포함), UX/UI 또는 영상, 제작 가능성.
2. 각 축은 creative-review의 검수 결과 형식(총평 ~ 최종 승인 여부)으로 보고하게 한다.
   UX/UI일 때 두 축에 화면별 목적·핵심 과업을 전달한다. 축 A는 그 목적과 선택 전략의 일치를 판단하고, 축 B는 [UI-QUALITY.md](UI-QUALITY.md) §2~4에 따라 시각·UX 비평과 구현 점검을 별도 절로 작성한다. 검색 기록이 있으면 채택·기각 근거와 미검증 조건도 입력에 포함한다. 검수 축을 추가하지 않는다.
   실행 가능한 UI·웹 코드 산출물은 [VISUAL-QUALITY.md](VISUAL-QUALITY.md)의 `실행 검증 로그`가 필수다. 로그 누락이나 가용한 검증의 미수행은 Critical로 처리한다. 비실행 산출물은 `검증 불가: 비실행 산출물`, 실행 환경·도구가 제한되면 시도한 방법·미검증 항목·제외 사유를 기록하고 실제 기능 결함과 구분한다. 미검증 항목을 기능 통과로 처리하지 않고 필요한 수용 체크의 검증 범위를 제한해 보고한다.
3. 두 보고를 병기해 사용자에게 전달한다. 병합하거나 재정렬하지 않는다.
4. Critical이 하나라도 있으면: 해당 이슈를 만든 단계의 실행 주체가 수정하고, 수정 후 **그 축만** 재검수한다. 위임할 수 없으면 주 에이전트가 수정한다.
5. 두 축 모두 Critical 0건이면 통과본을 `outputs/final/YYYY-MM-DD_<project>_final.md`로 저장하고 사용자에게 최종 보고한다.

## 핵심 모드 조항

핵심 모드에서도 검수 독립성은 줄이지 않는다 — 제작한 맥락이 자기 결과를 완성도 판정하면 자기 검수가 된다(수치는 [RUN-BUDGET.md](RUN-BUDGET.md)).

- **축 B(완성도)는 제작과 다른 실행 맥락에서 수행한다.** 위임이 허용되고 도구가 있으면 새 맥락의 검수 역할 1개에 축 B만 맡긴다(입력은 위 축 B 입력과 같고, 제작 과정의 자기 평가는 넘기지 않는다). 축 A(전략 일치)는 오케스트레이터가 수행한다. 리디자인의 축 C도 오케스트레이터가 수행한다.
- 위임할 수 없으면 주 에이전트가 creative-review 스킬을 읽고 축 A와 축 B를 순서대로 각각 기록하되, 축 B는 제작 맥락의 자기 평가를 재사용하지 않고 실물·렌더·실행 검증 로그를 처음부터 다시 열어 판정한다(재열람 의무). 이때 축 B 보고 첫머리에 제약 `동일 맥락 검수 — 제작과 같은 실행 맥락에서 수행, 재열람으로 보완`을 표기한다.
- 두 축의 보고는 여전히 분리 작성하고 합치지 않는다. Critical만 수정 루프를 돌리고(수정 후 해당 축만 재점검), Major 이하는 기록만 남긴다.
- 같은 산출물에서 Critical이 2회 연속 나오면 검수 단계를 전체 모드 수준으로 승격한다([RUN-BUDGET.md](RUN-BUDGET.md)의 단계별 승격).
