# 실행 예산 — 모드별 작업량·승격 신호·비용 기록

진행 모드(전체/핵심)가 단계마다 쓰는 작업량의 수치와 신호를 한곳에 둔다. gx-design·gx-redesign 본문은 이 문서를 링크하고 수치를 다시 적지 않는다.
결정·승인 재사용은 [HOST-COMPAT.md](HOST-COMPAT.md)가 정본이다. 모드·승격은 이미 확정·위임된 결정을 다시 열지 않으며 미확정 필수 결정의 응답 대기를 생략하지 않는다. 이 문서는 내부 작업량과 수정 예산을 정한다.

## 단순 작업의 경량 실행 기본값

- 범위가 정해진 단순 audit·polish는 **오케스트레이터 1개**로 시작한다. 자동 리서치·전략·서브에이전트 분기 없이 필요한 원본·규칙·기존 근거만 읽고 관찰한다. 필수 의도가 미확정이면 관련 작업의 응답 대기는 유지하며 질문 수에 임의 상한을 두지 않는다.
- 최초 관찰은 **대표 상태 1개**와 승인 범위의 필수 조건으로 시작한다. 추가 위험(관련 오류·긴 텍스트·모바일 배치·키보드·모션 등)이 있을 때만 해당 상태·폭·입력 방식을 더한다. 명시한 기기·여정·필수 수용 체크는 생략하지 않는다. 단일 컴포넌트 수정에 매 단계 2~3장 캡처를 만들지 않는다.
- 같은 실행 환경에서 DOM·스타일·콘솔·관련 과업 확인과 캡처를 일괄 수행하고 발견한 수정도 한 묶음으로 처리한다. 바뀌지 않은 조건의 근거는 유효성을 확인해 재사용한다. 작은 변경에 전 화면 재촬영·무관한 여정 재실행을 강제하지 않는다.
- 별도 검토가 필요한 작업 위험·규모(공유 토큰·여러 상태·핵심 과업·매체 전환 등)가 있고 위임 도구·권한이 가용할 때 **최종 축 B**를 제작과 다른 맥락 1개에 맡긴다. 단순 작업에 단계별 검수자·축별 팬아웃을 자동 생성하지 않는다. 별도 맥락이 없으면 자체 검수임을 표시하고 동일한 필수 판정 기준을 적용한다.
- 단계별 템플릿 문서를 모두 만들지 않는다. 단순 작업은 산출물 버전·범위·이슈/변경 ID·조건·판정·미검증·실행량을 담은 **간결한 이슈·변경·증거 로그** 하나로 인계한다. 사용자가 문서 자체나 전체 명세를 요청한 경우에는 해당 형식을 완성한다.

## 리서치 — frontier 기반 축 선택

- 조사 축(시장 / 경쟁사 / 사용자 / 트렌드)은 **브리프에 아직 열린·미검증 질문이 남은 축만** 실행한다. 사용자 자료·프로젝트 파일로 답이 난 축은 실행하지 않고 리포트에 `생략: 근거`로 기록한다.
- 외부 출처 열람 상한: 전체 모드는 **축당 외부 출처 8개**, 핵심 모드는 통합 리포트 1개에 **외부 출처 5개**.
- 상한에 도달하면 더 열지 않는다 — 남은 질문은 `미검증`으로 남기고 전략 단계에 넘긴다.
- 열린 질문이 있는 축이 없으면 추가 리서치·별도 리포트를 생략하고 기존 근거를 짧게 연결한다. 필요한 질문이 남았을 때만 해당 축을 조사한다.
- 핵심 모드 통합 리포트 분량 상한은 100줄이다(보충 리서치 1회도 같은 상한).

## 전략 — 스케치 → 선택 → 확장

- 방향이 이미 확정된 부분 수정·점검에는 전략 후보를 만들지 않는다. 방향이 열린 작업은 [DESIGN-IT-TWICE.md](DESIGN-IT-TWICE.md)를 따른다.
- 핵심 모드: 한 주체가 **추천 1안**을 제시하고 실제 판단 차이가 필요할 때만 **비교 1안**을 추가한다. 팔레트만 바꾼 후보나 요청하지 않은 전체 화면 세 벌을 만들지 않는다.
- 전체 모드 또는 **명시적 3안** 요청: 철학이 다른 **스케치 3안**(각 10~15줄)을 유지한다. 위임 권한·도구·병렬 작성의 실익이 있으면 독립 작성하고, 없으면 주 에이전트가 순서대로 쓴다.
- 필요한 전략 선택 또는 기존 위임을 확인한 뒤 채택 1안만 확장한다. 단순 작업은 별도 전략 확장 문서를 강제하지 않는다.
- 사용자가 다른 안의 확장을 요청하면 그 안만 추가 확장한다(사용자 결정).
- 사용자가 스케치 3안을 모두 거절하면 전략 선택 게이트 미통과로 본다. 승격 후 새로 쓴 스케치를 제시하고 선택을 다시 받는다. 다른 승격 신호는 이미 통과한 게이트를 다시 열지 않는다.

## 제작 분량

핵심 모드의 분량 기준은 **필수 섹션 + 화면(씬)당 상한**이다 — 총량 상한을 두지 않아 다화면 명세가 잘리지 않게 한다.

| 단위 | 상한 |
|---|---|
| 공통 섹션(제작 목표·적용 전략·토큰·자체 검수·미확정 사항·수용 체크 등) | 60줄 |
| UI 화면 1개 | 화면당 40줄 |
| 영상 씬 1개 | 씬당 15줄 |

명세 납품에서는 필수 섹션(creative-production 매체별 필수 섹션)이 상한보다 우선한다 — 상한 때문에 필수 섹션을 빼지 않는다. 전체 모드는 분량 상한을 두지 않는다. 단순 audit·polish의 결과 기록에는 매체별 명세 템플릿을 적용하지 않고 경량 로그를 쓴다.

## 검수 — 독립성

- 전체 모드: 축별 분리 검수([REVIEW-AXES.md](REVIEW-AXES.md)).
- 핵심 모드: 축 B 보고 머리에 `독립 검수(별도 맥락)`(별도 맥락이 실제 수행했을 때) 또는 `재열람 기반 자체 검수(동일 맥락 검수)`(그 외)를 쓴다. 전자는 산출물·브리프/전략·필수 기준·재현 정보와 축 규칙을 받고 제작자의 자체 검수 절은 첫 판단 입력에서 제외한다. 후자도 실물을 처음부터 다시 관찰한다. 두 경우 모두 직접 관찰 기록 후 원시 로그를 대조한다([REVIEW-AXES.md](REVIEW-AXES.md)).

## 단일 수정 예산

- 같은 승인 산출물·범위에 **기본 총 3회**를 배정하며 **제작자 polish + 검수 후 수정**을 합산한다. 이는 **상한이며 필수 작업량이 아니다**. 제작·실물화·축별 검수마다 별도 3회를 만들지 않는다. 명시적으로 위임된 다른 예산이 있으면 그 값을 기록해 적용한다.
- 1회는 같은 산출물에서 한 번에 발견한 문제의 **관찰 → 묶음 수정 → 재검증** 주기다. 관찰·판정은 최소 1회 수행하되 결함이 없으면 수정 없이 종료하고 수정 회차는 0이다. 스크린샷 수·렌더 수·도구 호출 수는 회차와 따로 센다.
- 시작 시 `적용 산출물 | 범위 버전·수정 ID 집합 | 필수 수용 조건 | 총예산 | 사용 회차 | 남은 회차`를 기록한다. 새 화면·새 매체·역할 교체·최종 내보내기로 예산을 자동 초기화하지 않는다. 이미 승인한 범위를 조용히 확대하지 않는다. 수정이 새로 만든 회귀는 관련 범위로 포함한다.
- 가장 큰 필수 문제부터 묶어 수정한다. 감사(audit)는 읽기 전용 관찰이며 수정 회차를 쓰기 위해 원본을 변경하지 않는다.
- 예산이 끝나도 필수 Critical·Major가 남거나 필수 수용 조건이 미검증이면 통과시키지 않는다. 남은 문제·증거·필요 작업을 보고하고 **추가 수정 / 범위 축소 / 예외 수용 / 종료**를 구별한다. 기존 위임 범위·실행 예산으로 허용되는 추가 작업은 진행하고, 권한 밖의 추가 범위·예산만 구체적으로 확인한다. 예외 수용을 해결된 통과로 바꾸지 않는다.
- 승격은 검수 깊이를 바꾸며 총예산·수정 범위·승인을 자동 갱신하지 않는다. [REVIEW-AXES.md](REVIEW-AXES.md)의 영향 기반 재검수를 같은 회차에 포함한다.

## 규칙 문서 읽기

VISUAL-CRAFT·VISUAL-QUALITY·MOTION·UI-QUALITY·ANTI-TELL-CHECKLIST·PROMPT-PLAYBOOK은 각 문서 머리의 **읽기 지도**(`산출물 유형 | 읽을 절 | 건너뛸 절`)를 따른다. **변경되지 않은 규칙**은 실행 맥락별 **세션당 한 번** 읽고 경로·버전/해시·읽은 절을 캐시한다. 현재 매체·축·과업에 해당하는 절만 읽으며 파일·브리프·범위가 바뀌면 영향받는 절만 갱신한다. 검수·진단도 해당 축이 판정할 적용 절을 빠뜨리지 않되 무관한 매체까지 전체 재열람하지 않는다. 위임 시 경로·읽을 절·현재 범위와 유효한 근거를 전달한다. 다른 맥락에 읽지 않은 규칙을 읽었다고 간주하지 않는다.

## 단계별 승격

진행 모드는 **시작 깊이**일 뿐이다. 아래 신호가 생기면 **그 단계만** 전체 모드 수준으로 올린다.

| 신호 | 승격 대상 |
|---|---|
| 산출물이 3종 이상이거나 화면 6개 이상 | 리서치·제작·검수 중 해당 단계 |
| hard 톤 기준과 전략이 충돌 | 전략 |
| 사용자가 스케치 3안을 모두 거절 | 전략(스케치 재작성은 독립 작성으로) |
| 같은 산출물 검수에서 Critical이 2회 연속 | 검수(축 분리) 및 해당 제작 |

- 승격 시 사용자에게 한 줄로 고지한다: `[승격] <단계> — <신호>`. 승인을 다시 받지 않으며, 이미 통과한 게이트는 다시 열지 않는다.
- 세 스케치 모두 거절은 전략 선택 게이트 미통과이므로 승격 후 새 스케치 선택을 받는다. 그 밖의 승격 신호는 이미 통과한 게이트를 다시 열지 않는다.
- 승격은 그 단계에만 적용된다 — 다음 단계는 원래 모드로 시작한다(그 단계에서도 신호가 있으면 다시 승격).
- 반대로 전체 모드라도 해당 단계의 열린 질문이 없으면 경량 실행한다(리서치 절 참조).

## 비용 기록

- 매 단계 보고(4줄)에 **5번째 줄 `실행량`**을 붙인다:
  `실행량: 위임 N회 · 외부 열람 N건 · 렌더 N장 · 토큰 N(호스트가 제공할 때만, 아니면 미측정)`
- 셀 수 없는 값은 `미측정`으로 적는다. **추정치를 측정치처럼 쓰지 않는다** — 추정을 적어야 하면 `추정` 표기를 붙인다.
- 최종 보고 때 단계별 합계 표를 `outputs/final/YYYY-MM-DD_<project>_run-log.md`로 저장한다.

단순 작업은 단계별 보고·별도 run-log 파일을 강제하지 않고 경량 결과 로그에 같은 실행량을 한 번 기록한다. 시간·질문/재질문·위임·열람·렌더/캡처·수정 회차와 측정 가능한 토큰을 구분한다. 이 예산 규칙의 정적 검사 통과를 실제 속도 개선의 측정값으로 보고하지 않는다.

| 단계 | 모드(승격 여부) | 위임 | 외부 열람 | 렌더 | 토큰 |
|---|---|---|---|---|---|
| 단계 0 브리프 | 핵심 | 0 | 0 | 0 | 미측정 |
| … | … | … | … | … | … |
| 합계 | | | | | |
