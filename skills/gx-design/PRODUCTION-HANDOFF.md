# PRODUCTION-HANDOFF — 실물 제작 게이트

명세 문서와 실물은 산출물 상태를 따로 기록한다. 영상 명세는 MP4, 이미지 명세는 PNG의 완성을 대신하지 않는다. 실물 요청은 대표 실물 제작·최종 파일 검수까지 수행하며, 명세 검수 통과를 최종 실물 통과로 옮겨 적지 않는다.

**이미 확정·위임된 경로**(처음 요청·브리프·현재 결정 버전의 사용자 승인 포함)는 재사용하고 같은 실물 제작 승인을 다시 묻지 않는다. [HOST-COMPAT.md](HOST-COMPAT.md)의 결정 계약으로 확인한 미확정 필수 결정에만 질문하고 의존 제작은 응답까지 기다린다. 산출물·방식이 달라졌으면 영향받는 결정만 갱신한다.

문서 자체(브랜드 가이드·전략 문서·카피 등)나 Gemini 프롬프트만 요청했으면 해당 결과물을 완성하고 종료한다. 요청하지 않은 이미지·영상 생성을 추가하지 않는다. 문서·프롬프트 완성과 생성 실물의 검수 상태를 분리한다. BX의 가이드와 실제 시각 자산을 함께 요청했으면 각각의 완료 상태를 확인한다.

## 0. 산출물·영역별 분류

프로젝트 전체에 한 분류를 붙이지 않고 **영역별 사용 목적 / 실제 동작 또는 연출 / 납품 형식**을 구분한다. 예: 홍보 랜딩의 CTA·문의 폼은 실제 UI, 히어로 안의 커서 데모는 소개 연출, 형식은 각각 실행 코드·영상일 수 있다. 홍보 목적도 실제 버튼·폼의 과업 검증을 면제하지 않으며, 연출 클릭으로 실제 앱 기능 통과를 주장하지 않는다. 선택적인 소개 장면 경로는 [PRODUCT-SCENES.md](PRODUCT-SCENES.md)를 참고한다.

## 1. 질문 구성

경로가 미확정일 때만 아래 선택지를 사용한다. 경로 병행이 가능하면 그 사실을 명시하고, 추천 경로와 근거를 선택지보다 먼저 제시한다.
결과물 유형별 옵션:

| 결과물 유형 | 옵션 4개 |
|---|---|
| 영상 | 코드 렌더링(Remotion·FFmpeg → 실제 MP4) · Gemini 프롬프트(Veo 계열 영상 생성) · 편집 도구 핸드오프(브리프에서 정한 도구 기준 체크리스트) · 문서로 종료 |
| 이미지·그래픽 | 코드 렌더링(HTML/SVG → PNG) · Gemini 프롬프트(이미지 생성) · .pen 시안(pencil MCP 가용 시, 아니면 디자인 툴 가이드) · 문서로 종료 |
| UI | 프로토타입(frontend-design 스킬) · .pen 시안 · Gemini 프롬프트(비주얼 목업) · 문서로 종료 |

BX처럼 산출물이 혼합(시각 자산 + 가이드 문서)인 프로젝트는 요청된 시각 자산(로고·키 비주얼·SNS 그래픽 등)에 이미지·그래픽 경로를 적용한다. 이미 확정한 자산·제작 방식은 재사용하고 미확정 필수 결정만 확인한다. 가이드 문서만으로 실제 자산 요청을 완료 처리하지 않는다.

**영상·이미지 유형에서 Gemini 옵션은 필수다** — 이 플러그인의 주 사용자층(개발자·사업부 실무자)이 생성 도구로 Gemini를 주로 쓴다. 어떤 경우에도 빼지 않는다.

추천 배치 — 아래 기준으로 고른 추천 경로를 **옵션 목록의 첫 번째 위치로 옮기고** label 끝에 "(추천)"을 붙인다. 표의 나열 순서는 옵션 순서가 아니다. label은 경로명만 짧게 쓰고, 괄호 설명은 description에 넣는다.

- UI·터미널·타이포·도형·차트 중심 산출물 → **코드 렌더링** (텍스트 정확도 100%, 수정 후 재렌더 가능)
- 실사·인물·일러스트·질감 중심 산출물 → **Gemini 프롬프트** (코드로 재현할 수 없는 영역)

**경로별 확인 문항** — 선택된 경로가 아래에 해당하면 같은 질문·선택 흐름에서 이어서 확인한다. 브리프·명세에 이미 있으면 묻지 않고 재사용 사실만 밝힌다.

- 영상 코드 렌더링: **fps**(24/30/60 — 명세 기준 추천)와 **게시 플랫폼**(유튜브 가로형 / Reels·Shorts·TikTok 세로형 / 사내 상영 등). fps는 씬 길이의 프레임 검산, 게시 플랫폼은 안전영역 확인에 쓴다([MOTION.md](MOTION.md) §B1·B6).
- UI 프로토타입·코드 렌더링: **검증 여정** — 요청·브리프의 핵심 여정과 대상 기기를 재사용한다. 여정이 없으면 명시된 화면별 핵심 과업으로 확인하고, 과업·기기를 결정할 수 없는 필수 의도가 남았을 때만 "어떤 흐름을 실제로 눌러 확인할지"(예: 메인 → 상세 → 장바구니)를 묻는다. 이 여정은 [VISUAL-QUALITY.md](VISUAL-QUALITY.md)의 여정 시나리오로 실행 검증 로그에 남는다.

사용자 선택이 추천과 달라도 그대로 진행한다. 단, 선택 경로가 산출물의 핵심 요소와 구조적으로 충돌하면(예: 타이포 중심 산출물에 생성형 경로 — 정밀 온스크린 텍스트가 후삽입으로 빠진다) 위임 전에 그 한계와 보완책(코드 렌더링 병행, 자막 후삽입 계획 등)을 한 번 고지하고 진행한다. 선택을 번복시키려는 재질문은 하지 않는다.

## 2. 경로 A — 코드 렌더링

영상은 Remotion(React 컴포지션 → MP4) 또는 FFmpeg, 이미지는 HTML/CSS → 스크린샷(Playwright) 또는 SVG로 만든다.

- 명세의 프레임·픽셀·색상 값을 그대로 코드로 옮긴다. 환경 제약으로 바꾼 값(폰트 폴백 등)은 [가정] 표기 후 보고한다.
- 모션이 있으면 [MOTION.md](MOTION.md)를 적용한다 — UI 인터랙션은 §A, 영상·모션 그래픽은 §B(확정한 fps로 씬 합 = 러닝타임을 프레임 단위로 검산, 게시 플랫폼 안전영역 확인). Remotion·FFmpeg가 없으면 설치를 강제하지 않고 다른 경로를 안내한다.
- UI 프로토타입·코드 렌더는 확정한 검증 여정을 모바일·데스크톱 대표 폭에서 실제로 따라가 확인한다.
- [VISUAL-QUALITY.md](VISUAL-QUALITY.md)에 따라 대표 상태 1개와 관련 위험 조건부터 직접 관찰·판정하고 발견한 문제만 묶어 수정한다. 캡처는 위험·필수 조건에 따라 추가하며 매 단계 고정 장수를 만들지 않는다. 제작자 polish와 검수 후 수정은 [RUN-BUDGET.md](RUN-BUDGET.md)의 단일 총예산을 공유한다. 신규 제작은 대표 결과 확인 후 확장하고 실제 납품 파일을 확인하며, 부분 수정은 관련 영역·회귀만 재검증한다.
- 제작을 위임하는 경우 제작 역할에 [VISUAL-QUALITY.md](VISUAL-QUALITY.md) 경로를 전달한다. 위임할 수 없으면 주 에이전트가 그 문서를 읽고 같은 시각 품질 루프를 수행한다.
- 실물은 outputs/final/에 저장하고, 렌더 프로젝트는 outputs/video/ 같은 별도 폴더에 남겨 재렌더 가능하게 한다.
- 의존성 설치·렌더 환경 구성은 오케스트레이터가 직접 수행해도 된다(위임 예외).
- 검수자에게 URL/파일·실행 방법·인증 상태·시작 화면·fixture 초기화·실행 도구 능력을 전달한다. 최종 파일의 버전 또는 해시와 관찰 조건을 [REVIEW-AXES.md](REVIEW-AXES.md)의 검수 기록에 연결한다. 내보내기·최종 저장 후 바뀐 파일은 영향받는 검수를 갱신한다.

## 3. 경로 B — Gemini 프롬프트 패키지

실행 전 [HOST-COMPAT.md](HOST-COMPAT.md)의 위임 규칙과 [creative-production 스킬](../creative-production/SKILL.md)의 역할·산출물 계약을 읽는다. 위임이 허용되고 서브에이전트 도구가 있으면 제작 역할에 final 명세 경로, [PROMPT-PLAYBOOK.md](PROMPT-PLAYBOOK.md) 경로, 위임 11항목을 전달한다. 위임할 수 없으면 주 에이전트가 creative-production 역할·산출물 계약에 따라 final 명세와 PROMPT-PLAYBOOK.md를 읽고 Gemini 프롬프트 패키지를 제작한다. 어느 경로든 패키지 구조·프롬프트 규격·텍스트 정책은 PROMPT-PLAYBOOK.md를 정본으로 따른다.
저장: `outputs/final/YYYY-MM-DD_<project>_gemini-prompts.md`

핵심 원칙 요약(상세와 예외는 PROMPT-PLAYBOOK):

- 생성 설정값(종횡비·해상도·클립 길이)은 프롬프트 문장이 아니라 UI 설정으로 분리 안내한다.
- 컷마다 후속 수정 프롬프트 2~3개를 포함한다 — 재롤이 아니라 같은 대화의 부분 수정이 기본 경로다.
- 온스크린 텍스트는 PROMPT-PLAYBOOK §4 정책을 따른다(정밀 로고·한글 문장은 후삽입, 짧은 영문 1~10자는 허용).
- 영상은 클립당 8초 한계로 분할하고 모든 클립에 오디오 지시를 넣는다. 모션 서술은 [MOTION.md](MOTION.md) §B의 어휘(진입 감속·전환 체계·시그니처 모션 1개)를 따른다.
- 프롬프트 본문은 영어가 기본(생성 안정성), 사용자가 원하면 한국어로 쓴다.
- 코드 렌더링과 병행 선택되면 첫 컷은 같은 산출물의 동일 장면 재현(A/B 선택용)이다 — 무드·보완 컷만으로 채우지 않는다(PROMPT-PLAYBOOK §6 동일 산출물 A/B 원칙).

## 4. 경로 C — 편집 도구 핸드오프

브리프에서 정한 편집 도구(CapCut 등) 기준의 단계별 실행 체크리스트를 정리한다.
production 패키지에 편집 가이드가 이미 있으면 새로 만들지 않고 해당 절의 위치와 남은 작업만 안내한다.

## 5. 문서로 종료

실물을 만들지 않는 선택도 유효하다. 남은 사용자 액션(게시·트래킹 등)을 요약하고 종료한다.

## 완료 기준

- 현재 결정 버전의 요청·승인·위임으로 산출물과 경로가 확정되어 있다. 미확정 필수 결정은 응답을 받았고, 이미 확정한 선택은 재사용했다.
- 선택된 각 경로의 산출물이 지정 위치에 저장되었고 결과·검수 상태를 보고했다. 단순 작업은 별도 단계 문서 대신 기존 산출물과 간결한 이슈·변경·증거 로그를 연결한다.
- 복수 경로를 선택받았으면 전부 완료했다.
- 최종 버전의 검수 상태를 경로별로 보고했다. 범위 내 필수 Critical·Major 미해소는 `수정 필요`, 필수 증거 부재는 `미검증`, 명시적 결함 수용은 `예외 수용`으로 남긴다. 예산 소진이나 문서 통과만으로 실물 통과를 선언하지 않는다.
