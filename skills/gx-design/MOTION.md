# MOTION — UI 인터랙션·모션 그래픽·영상 모션 규칙

모션이 있는 산출물의 제작·진단·검수가 공통 참조하는 모션 규칙. §A는 emil-design-eng의 UI 모션 규칙을 우리 문장으로 **흡수**한 것이고, §B는 gx-design 자체 규칙이다(외부 스킬 런타임 의존 없음).

**상위 규칙**: 디자인 톤 기준([DESIGN-TONE-ANCHOR.md](DESIGN-TONE-ANCHOR.md))과 브리프가 이 문서보다 우선한다. 모션 강도(MOTION 다이얼)는 [VISUAL-CRAFT.md](VISUAL-CRAFT.md) §2에서 정하고, 이 문서는 그 강도 안에서 지킬 실행 규칙이다.

**읽기 지도**

| 산출물 유형 | 읽을 절 | 건너뛸 절 |
|---|---|---|
| UI 인터랙션(웹·앱·코드 렌더 화면) | §0·§A·§C | §B |
| 모션 그래픽·영상(코드 렌더·편집 도구 핸드오프·영상 프롬프트 모션 서술) | §0·§B·§C | §A |
| UI와 영상이 섞인 산출물(예: 랜딩 스크롤 연출 + 임베드 영상) | §0·§A·§B·§C | — |
| 모션 없는 산출물 | — (로드하지 않는다) | 전체 |
| 모션 진단·검수 | 해당 분기 행의 절 전체 | 해당 분기 행이 건너뛰는 절 |

검수·진단 역할은 '건너뛸 절'을 적용하지 않는다 — 자기 축이 판정하는 절 전체를 읽는다. 모션 진단·검수는 해당 분기 규칙 전체를 읽는다. `출처` 절은 모든 유형에서 건너뛴다.

## 0. 적용 범위 분기

| 분기 | 대상 | 시간 단위 |
|---|---|---|
| §A UI 인터랙션 | 웹·앱 화면, 코드 렌더 화면의 hover·press·진입·전환 | ms |
| §B 모션 그래픽·영상 | Remotion·FFmpeg 렌더, 편집 도구 핸드오프, Veo 등 영상 프롬프트의 모션 서술 | 프레임(초 병기) |

**§A 규칙을 영상에 적용하지 않는다** — 예: "300ms 이하"는 사용자가 기다리는 UI의 규칙이지, 시청자가 보는 영상에는 의미가 없다. 반대로 §B의 오버슈트·퇴장 가속을 UI로 끌어오지 않는다. 한 산출물에 둘이 섞이면(예: 랜딩의 스크롤 연출 + 임베드 영상) 요소마다 분기를 정해 명세에 적는다.

## A. UI 인터랙션

### A1. 빈도가 모션을 정한다

| 사용 빈도 | 예 | 모션 |
|---|---|---|
| 하루 100회 이상 | 단축키, 커맨드 팔레트 | 없음 |
| 하루 수십 회 | hover, 리스트 이동 | 제거하거나 최소로 |
| 가끔 | 모달, 드로어, 토스트 | 표준 |
| 드묾·첫 사용 | 온보딩, 완료 축하 | 연출 허용 |

- 키보드 단축키로 반복 실행하는 고빈도 동작(커맨드 팔레트 토글·목록 이동 등)은 애니메이션하지 않는다. 포커스 가시성과 키보드로 여닫는 메뉴의 열기·닫기는 A1 빈도 및 A8을 따른다.
- 모든 모션은 목적 하나를 가진다: 공간 연속성 / 상태 표시 / 동작 설명 / 입력 피드백 / 갑작스런 등장 방지. 목적을 한 줄로 못 쓰면 뺀다.

### A2. 이징

- 진입·등장: ease-out(기본값). 화면 안에서 위치 이동: ease-in-out. hover·색 변화: ease. 등속이 맞는 것(마퀴·진행바): linear.
- **UI에 ease-in을 쓰지 않는다** — 시작이 굼떠 반응이 늦은 것처럼 느껴진다.
- 브라우저 기본 곡선은 약하다. 권장 곡선:
  - 강한 ease-out: `cubic-bezier(0.23, 1, 0.32, 1)`
  - 강한 ease-in-out: `cubic-bezier(0.77, 0, 0.175, 1)`
  - 드로어(iOS 시트 느낌): `cubic-bezier(0.32, 0.72, 0, 1)`

### A3. 지속시간

| 요소 | 지속시간 |
|---|---|
| 버튼 press 피드백 | 100–160ms |
| 툴팁·작은 팝오버 | 125–200ms |
| 드롭다운·셀렉트 | 150–250ms |
| 모달·드로어 | 200–500ms |

- **UI 인터랙션은 300ms 이하가 기본**이다. 예외는 모달·드로어와 마케팅 페이지의 스크롤 연출뿐이다.
- 나가는 모션은 들어오는 모션보다 짧게 — 닫기는 이미 내린 결정이다.

### A4. press·hover

- 누를 수 있는 요소는 `:active`에서 `scale(0.97)`(0.95–0.98 범위)로 눌림을 보여 주고 `transition: transform 160ms ease-out`을 건다.
- hover 효과는 `@media (hover: hover) and (pointer: fine)` 안에서만 정의한다 — 터치 기기에서 hover가 눌린 채 남는 것을 막는다.

### A5. 진입

- `scale(0)`에서 시작하지 않는다 — 무(無)에서 튀어나오는 것처럼 보인다. `scale(0.9)` 이상 + `opacity: 0`에서 시작한다.
- 팝오버·드롭다운의 transform-origin은 트리거 쪽 모서리로 둔다. 화면 중앙에 뜨는 모달만 center.

### A6. 금지

- `transition: all` — 바꿀 속성을 명시한다.
- width·height·padding·margin 애니메이션 — layout을 다시 계산한다. transform·opacity만 움직인다.
- 빠르게 반복 발동되는 요소(hover·토글)에 keyframes — 중간에 끊을 수 없다. 중단 가능한 transition을 쓴다.
- stagger 항목 간격 80ms 초과, stagger가 끝나기 전 조작을 막는 것.

### A7. 스프링

- 드래그 모멘텀, 중간에 방향을 바꿀 수 있는 제스처에만 쓴다. bounce는 0.1–0.3.
- 차트·잔액처럼 기능성 데이터 표시에는 쓰지 않는다 — 출렁이는 숫자는 신뢰를 깎는다.

### A8. reduced-motion — "0이 아니라 덜"

`prefers-reduced-motion`에서 모션을 전부 끄지 않는다. opacity·색 전환은 상태 피드백이므로 유지하고, 이동·확대·패럴랙스·자동 재생을 제거한다.

## B. 모션 그래픽·영상

### B1. 시간 단위는 프레임

- fps(24/30/60)를 명세 머리에 고정한다. 도중에 바꾸지 않는다.
- 씬 길이는 `초(프레임)`로 병기한다 — 예: `2.5초(75f @30fps)`.
- 씬 합 = 러닝타임을 **프레임 단위로** 검산한다. 초 단위 반올림 합은 렌더에서 어긋난다.

### B2. 가독 홀드

- 화면 텍스트는 등장 연출이 끝난 뒤 정지 홀드를 둔다 — 움직이는 동안은 읽히지 않는다.
- 홀드 길이는 "소리 내어 두 번 읽을 수 있는 시간"을 기본으로 잡고, 명세에 텍스트별 홀드 초를 적는다. 고정 수치 규칙은 두지 않는다.

### B3. 이징 어휘 (UI와 별도)

- 진입은 감속, 퇴장은 가속 허용, 강조는 오버슈트 허용, 티커·롤링은 등속.
- 같은 역할의 모션은 같은 곡선 — 씬마다 곡선이 바뀌면 산만해진다.

### B4. 전환 체계

- 한 영상의 전환 종류(컷·디졸브·매치컷·마스크·푸시)는 2~3종으로 제한하고 역할을 정한다 — 예: 챕터 구분 = 마스크, 씬 내 = 컷.

### B5. 훅과 리듬

- 첫 1~3초에 핵심 메시지 또는 시각 사건을 둔다. 로고 인트로로 시작하지 않는다(브리프가 요구하면 예외).
- BGM이 있으면 비트 기준 컷 포인트를 명세에 적는다.

### B6. 플랫폼 안전영역

- 세로형 숏폼(Reels·Shorts·TikTok)은 상단·하단·우측 UI 영역(계정명·캡션·버튼)에 자막·CTA·로고를 두지 않는다.
- 게시 플랫폼을 명세에 적고, 렌더 확인 때 해당 플랫폼의 안전영역 가이드를 겹쳐 본다.

### B7. 절제

VISUAL-CRAFT §5를 시간축에 적용한다 — 시그니처 모션은 하나, 나머지는 조용히. 모든 요소가 움직이면 아무것도 강조되지 않는다.

### B8. 코드 렌더 도구

- Remotion·FFmpeg로 렌더할 수 있다. Remotion이 설치돼 있고 호스트에 공식 Remotion 스킬이 있으면 그 지침을 선택 참조한다.
- 도구가 없으면 설치를 강제하지 않는다 — [PRODUCTION-HANDOFF.md](PRODUCTION-HANDOFF.md)의 다른 경로(Gemini 프롬프트 패키지·편집 도구 핸드오프)를 안내한다.

## C. 모션 점검 출력

모션 진단·검수 지적은 이슈당 1행 표로 쓴다. "Before:/After:" 줄을 나열하지 않는다.

| 요소·위치 | Before | After | Why |
|---|---|---|---|
| 드롭다운(헤더 메뉴) | `transition: all 400ms ease-in` | `opacity, transform 180ms cubic-bezier(0.23, 1, 0.32, 1)` | A2 ease-in 금지 · A3 드롭다운 150–250ms · A6 all 금지 · 관찰법: 코드 줄·선택자, 실행 조건·뷰포트, 캡처 |

- Why에는 근거 규칙 번호(A1~A8, B1~B8)를 적고, 각 행에 관찰법(코드 줄·선택자 / 실행 조건·뷰포트 / 캡처)을 기록한다. gx-redesign의 축 C는 같은 관찰법으로 다시 확인한다.
- 심각도는 기존 체계(Critical/Major/Minor)를 따른다 — 조작 차단·reduced-motion 무시는 Major 이상.
